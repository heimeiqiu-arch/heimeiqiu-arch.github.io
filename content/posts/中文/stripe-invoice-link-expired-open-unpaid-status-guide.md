# Stripe 发票链接过期或账单未支付怎么办？状态与重发操作指南

客户打开 Stripe 发票邮件时，可能发现付款链接已经失效；商家也可能看到发票仍显示 Open、Past Due 或 Retrying，不确定该继续提醒客户、重新发送账单还是创建新发票。处理前要先区分发票状态和发票页面链接状态。链接失效不一定代表发票已经作废，发票显示逾期也不一定代表支付已经失败到无法补救。

Stripe 发票有 Draft、Open、Paid、Uncollectible 和 Void 等状态。官方说明中，Past Due 或 Retrying 这类 Dashboard 徽标不是独立的发票状态，发票本身仍可能处于 Open。每个状态允许的操作不同，因此商家应先看 Invoice 对象当前状态、到期日、付款尝试和客户付款记录，再决定是否重发链接。

## 先区分发票状态和付款页面链接

发票状态回答的是“这张账单目前处于什么处理阶段”；Hosted Invoice Page 链接则是客户查看账单或进行付款的页面入口。邮件中的链接可能过期，但发票对象仍然存在，也可能仍然开放等待付款。相反，发票状态如果已经 Void，客户即使还保留旧邮件，也不能把它当作仍然有效的应收账款。

发票为 Draft 时，通常仍处于编辑准备阶段。Stripe 帮助中心说明，草稿发票尚未最终确认，客户还不能通过它付款。发票为 Open 时，表示发票已 finalise 并等待客户付款。Paid 表示该发票已经被标记为已支付；Uncollectible 是商家将其标记为无法收回的状态；Void 则表示发票已作废且进入终止状态。

因此，客户说“链接打不开”时，先让商家查看 Invoice 状态，而不是马上复制一条新账单。若原账单仍 Open，通常应围绕同一张发票恢复客户访问；若金额、客户或商品信息需要更改，先确认该状态允许什么操作。已经 finalise 的发票不能像草稿那样随意编辑所有字段，可能要使用修改发票、贷项通知单、作废后复制等符合 Stripe 流程的方式。

## 为什么 Stripe 发票链接会过期？

Stripe 官方帮助说明，发票邮件中的 Hosted Invoice Page、PDF 或贷项通知单链接会根据发票到期日和最终确认时间设置有效期限。链接失效后，商家仍可从 Dashboard 重新发送发票，或获取新的 Hosted Invoice Page 链接。若发票是通过 Dashboard 或 API 发给客户的，客户打开过期链接时也可能看到通过邮箱恢复的流程，重新获取一封带新链接的发票邮件。

客户可能很晚才打开邮件、从旧的转发邮件访问链接，或把浏览器收藏的账单页面当作永久有效入口。也可能是同一个客户收到多份发票邮件，误点了旧账单或已经替换的链接。邮件仍在收件箱里，不代表链接没有时限；客户可能只是记住了发票编号，而非当前页面入口。

商家要避免把链接过期与账单到期混为一谈。发票链接过期，关注的是页面访问；发票到期日则是付款条款和账款管理的信息。即使页面链接无法访问，发票可能仍然开放；即使链接还能够访问，发票也可能已 Paid、Void 或需要其他处理。判断时以 Stripe Dashboard 中发票对象状态为主。

## Dashboard 中怎样核对一张未付款发票？

先搜索客户姓名、邮箱、发票号码或 Invoice ID，确认当前打开的是正确账户和正式模式。再核对发票金额、币种、创建日期、到期日、客户资料、商品或服务描述以及发票状态。若同一客户有多张账单，按发票号码和日期逐一核对，避免把上一期账单的链接发给客户。

查看付款记录时，确认有没有已成功的 PaymentIntent、支付尝试失败信息、部分付款、退款或余额抵扣。若商家在 Stripe 之外收到了转账、支票或其他线下付款，应先确认款项确实到账，再按流程将发票标记为线下付款或 Paid out of band。Stripe 帮助中心说明，若客户通过其他渠道支付一张仍 Open 的发票，商家可以在 Dashboard 中将发票标记为线下已支付。

不要仅凭客户发来银行转账截图就修改发票状态。核实实际到账金额、币种、付款人、参考编号和入账日期，并检查该笔款项是否对应此发票。如果只收到部分金额，应按商家账务流程记录未结余额，而不是将整张发票标成全额已付。

## 发票是 Open 或 Past Due 时怎么处理？

Open 表示发票已 finalise，并等待付款。Dashboard 可能额外显示 Past Due 或 Retrying 徽标，但 Stripe 帮助中心指出，这些徽标并不代表新的发票状态；发票仍然是 Open。商家应根据付款记录判断是付款尚未尝试、自动收款失败后继续重试，还是客户尚未打开账单页面。

若客户没有收到发票邮件，核对 Invoice 中的客户邮箱是否正确、邮件是否被退信或进入垃圾邮件，然后从 Dashboard 重新发送。若客户访问的是过期链接，可以重新发送发票或在 Dashboard 中复制当前 Hosted Invoice Page 链接。发送前确认账单金额、到期日和收款说明仍有效，并通过已验证的联系人渠道发送。

若自动收款正在重试，不要在未检查 PaymentIntent 和订阅状态前再向客户发送一份新发票。重复创建账单可能让客户误以为需要支付两次。可在邮件中清楚说明现有发票编号、当前待付款余额和处理方式。如果客户希望使用另一种付款方式，确认原发票是否支持更新付款方式或需要商家重新发送。

## 什么时候重新发送，什么时候要改发票？

如果只是客户无法访问链接，但账单金额、客户和服务内容都正确，通常先重新发送原发票或提供新的 Hosted Invoice Page 链接。这样能保留同一发票的状态和账务关联，减少创建重复应收项目。客户收到新链接后，商家应记录发送日期，并确认同一账单没有被多个客服重复发送不同版本。

如果发票金额、客户、税务信息或服务项目有误，则应先看当前发票状态和 Stripe 支持的操作。Open 发票在 finalise 后，部分信息不可修改。Stripe 官方帮助建议对于需要更改的已 finalise 发票，可以根据情况使用贷项通知单、编辑发票流程，或作废并复制成一张新发票。具体可用选项要按 Dashboard 中实际显示的操作与当地账务要求处理。

Void 和 Uncollectible 也不能混用。Void 表示账单作废，不能再继续更改；Uncollectible 表示商家将其标记为无法收回，状态后续可根据 Stripe 支持的规则转成 Void 或 Paid。若只是客户忘记付款，不应随意标记为无法收回。修改账单前保存原始发票、客户沟通和退款或贷项记录，确保后续审计能看清更改原因。

## 客户已通过其他方式付款怎么办？

如果客户通过银行转账、线下收款或其他支付渠道付款，先将外部付款与 Stripe 发票匹配。核对到账日期、金额、币种和付款参考信息，确认没有款项退回或处理中。再使用 Stripe 支持的线下付款标记操作，使发票状态与实际收款保持一致。

如果 Stripe 仍对该发票发起自动扣款，而商家已经从其他渠道收款，要尽快核对自动收款设置和待处理支付，避免随后再次扣客户卡片。不要只在订单系统中写“已付款”而让 Stripe 发票继续保持 Open，这会造成后续提醒、收入报表或客户邮件与实际情况不一致。

若客户通过其他渠道只支付了部分金额，记录支付金额及尚未支付的余额，并按照公司会计流程处理。不要将部分收款误标为 Paid。若已在 Stripe 产生一笔误扣款，先确认该付款是成功、待处理还是授权状态，再决定是否退款或调整账单；给客户说明时应提供发票号码和付款参考，而非只说“系统扣错了”。

## 发票链接过期后的客户沟通模板

可以向客户说明：“我们核对了发票编号为某编号的账单，原邮件中的付款页面链接已过期，发票当前状态为某状态。我们已从 Stripe 重新发送了当前付款页面，请使用最新邮件中的链接，并核对金额和到期日。旧链接请不要继续使用。如您已经通过其他方式付款，请回复付款日期和参考编号，我们会先核对账款。”

若链接恢复流程要求客户输入邮箱，应提醒客户使用收到原发票的邮箱，并注意查看垃圾邮件文件夹。若商家不是通过 Dashboard 或 API 发出这张发票，Stripe 官方支持流程可能不同，客户需要联系商家确认付款信息。不要让客户把银行卡完整信息、密码或一次性验证码发送到邮件或客服聊天中。

## 如何减少发票邮件和账单重复？

为每张发票建立唯一业务订单号，并在发票备注或商家系统中保存 Stripe Invoice ID。重发邮件时继续使用同一张 Open 发票，不要为了“换链接”无意中创建一张重复账单。若确实需要新发票，先明确原发票是 Paid、Void、Uncollectible 还是仍 Open，并在新发票说明中关联原账单号和变更原因。

对订阅发票、一次性发票和线下付款分别建立处理流程。订阅发票可能与 Subscription、Invoice、PaymentIntent 等对象相关；一次性发票可能由 Dashboard 或 API 创建；线下收款则需要明确标记。客服和财务团队查看同一记录，可以避免一个人重新发送发票，另一个人同时创建新账单。

定期检查过期链接咨询、退信、付款失败重试和未收回账单。若经常有客户从旧邮件进入过期页面，可以优化邮件标题、提醒文字和客服知识库，明确发票编号、付款到期日以及需要时如何恢复链接。不要在页面里宣传固定链接永久有效，除非你确认当前产品规则确实支持这种说法。

## 常见问题

### 链接过期，发票会自动消失吗？

不一定。链接有效期和发票状态是不同问题。先在 Dashboard 查 Invoice 状态，再决定是否重新发送或修改账单。

### 客户可以自己恢复过期的发票链接吗？

Stripe 帮助中心说明，如果发票是通过 Dashboard 或 API 发给客户的，客户打开过期链接时可能可以输入邮箱，通过恢复流程重新收到带新链接的发票邮件。若页面没有该流程，联系商家重新发送。

### 发票显示 Past Due 是一个新的状态吗？

不是。Stripe 官方帮助说明，Past Due 或 Retrying 等徽标可能表示发票当前附加状态，但发票本身仍然可能处于 Open。查看具体付款尝试和发票字段。

### 已经线下收款，还要保留 Stripe 发票吗？

可以根据账务流程保留记录，并将已核实的线下付款关联或标记到发票上。这样能让 Stripe 发票状态与实际收款方式保持一致。操作前先确认付款到账，避免误标。

### 发票已 finalise 还能修改金额吗？

草稿与已 finalise 的发票允许的操作不同。Stripe 帮助中心说明，Open 发票中金额和客户等字段可能不能直接修改；需要按情况使用贷项通知单、发票编辑流程或作废并复制等方式。以当前 Dashboard 提供的选项为准。

### Uncollectible 和 Void 有什么区别？

Uncollectible 表示商家将账款标为无法收回，发票状态仍有 Stripe 规定的后续转换方式；Void 表示发票已作废且进入终止状态。不要把普通逾期账单直接当作已作废。

## 总结

Stripe 发票链接失效时，先分清页面链接和 Invoice 对象状态。确认账单仍 Open 且金额正确后，优先重新发送原发票或提供新页面链接；若客户已在线下付款，则先核实到账并更新发票状态；若账单内容需要调整，按照发票当前状态选择贷项通知单、编辑、作废或复制流程。使用发票 ID、订单号和付款参考进行匹配，可以减少重复收款、重复开票和账务不一致。

**发票处理检查单：**

- 确认正式模式或测试模式。
- 核对发票号码、客户、金额、币种和到期日。
- 查看 Draft、Open、Paid、Uncollectible 或 Void 状态。
- 检查付款尝试、已成功款项及外部渠道收款。
- 确认问题是链接过期还是发票本身状态变化。
- 重发前检查是否已有客服或财务发送了新链接。
- 需要修改已 finalise 发票时，按 Dashboard 提供的官方方式处理。
- 将新的链接发送时间和发票 ID 记回订单系统。
- 不要在客户未确认前通过新发票重复收款。
- 保留沟通记录和交易参考，同时保护客户付款资料。

*本文根据 Stripe 官方发票状态与链接过期说明整理；发票允许的操作会受状态、账户配置和所在地账务规则影响，请以 Dashboard 对该发票显示的选项为准。*

## 财务对账时的记录建议

账单发出、客户付款、Stripe 付款入账、银行打款可能分别发生在不同日期。对账时按 Invoice ID 和业务订单号关联每一步，并分别记录应收金额、已付金额、发票状态、付款渠道、币种和入账日期。不要只比较发票总额和银行单笔流水，因为 Stripe 打款可能聚合多张发票、扣除手续费或包含其他余额调整。

如果客户支付后发票仍 Open，核实支付是否关联到正确的 Invoice；若通过外部渠道收款，保留银行参考号和客户付款证明，并按流程标记线下支付。重复收到付款时，先检查两个 Stripe 对象是不是同一张发票的重试或不同订单，再处理退款。月底将 Open 余额与应收账款报表比较，检查已作废、无法收回、部分支付和退款的发票是否都采用一致的内部规则。

对于多币种业务，另建币种列，保留原始账单币种与实际结算币种，不要将汇率差额直接当作少收款。将未核销项目附上负责人和下一步处理日期，避免月末对账后仍无人跟进。
