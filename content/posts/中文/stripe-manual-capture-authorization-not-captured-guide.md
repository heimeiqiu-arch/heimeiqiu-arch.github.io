商户有时会在 Stripe Dashboard 看到付款已授权、客户银行卡出现待处理记录，但 Stripe 余额和订单系统还没有显示实际收款。这可能是集成启用了 manual capture（手动捕获）：付款授权先确认资金可用，商户随后才决定捕获全部或部分金额。授权与捕获是支付流程中的不同阶段，客户看到的银行待处理记录也不一定代表商户已经收到结算款。

手动捕获适用于某些需要先确认库存、最终金额或服务履约条件的业务，但它带来授权有效期、金额变化、取消和未捕获自动过期等管理要求。支付方式支持情况和授权期限会因卡网络、地区、交易方式和账户配置而异。请以 Stripe 对具体 PaymentIntent 显示的状态、capture_before 信息和当前官方文档为准。不要依据一个固定天数处理所有交易，也不要在对象状态不明时重复创建付款。

## 一、授权和捕获的区别

授权是向发卡行请求批准一定金额，通常会在客户卡片上形成待处理或预授权记录；捕获则是商户请求结算全部或部分已授权金额。PaymentIntent 使用自动捕获时，符合流程的付款会自动尝试捕获；使用 manual capture 时，授权成功后可能停留在 requires_capture，商户需在授权可用期内调用捕获操作。

客户看到银行 App 有一笔冻结或待处理金额，不必然表示最终结算已完成。银行可能在授权时展示临时记录，捕获后更新为正式交易，未捕获时释放额度也需要由发卡行处理。Stripe Dashboard 里的付款状态、PaymentIntent 的 amount_capturable、捕获记录与客户账单应结合查看。向客户解释时应明确付款处于授权还是已捕获，不要说“已经收款”来描述仅有授权的交易。

## 二、确认 PaymentIntent 状态

从订单记录找到 PaymentIntent ID，进入 Stripe Dashboard 核对 status、capture_method、amount、amount_capturable、currency、latest_charge 和相关时间。requires_capture 通常表示资金已授权、可供后续捕获；succeeded 则表示支付流程已完成，但仍要结合捕获金额与业务系统确认。requires_action、processing、requires_payment_method 等状态对应不同流程，不能统一当成授权成功。

确认关联订单是否为同一笔交易，尤其是客户重复点击付款、多个 PaymentIntent 使用相同金额或前端重试的情况。检查当前模式是 test 还是 live、是否在正确 Stripe 账户中查看，以及事件记录是否与数据库对象 ID一致。如果应用只把“授权成功”映射成“订单已支付”，应调整业务状态机，使待捕获订单与已捕获订单可区分，并避免在尚未收款时执行不可逆的履约。

## 三、为什么商户选择手动捕获

常见场景包括先确认库存、在发货前检查订单、根据实际使用量确定最终收费金额、租车或住宿服务中的押金流程，以及其他需要先保留授权再确定最终金额的业务。具体适用方式取决于支付网络和 Stripe 支持情况。手动捕获不是所有支付方式都支持，也不应仅因为“想晚点收钱”就默认适用。

设计时要说明什么时候授权、什么时候捕获、是否可能仅捕获部分金额、未捕获时会发生什么以及客户可能看到怎样的银行记录。尤其是订阅或持续性服务，授权和后续扣款涉及不同的客户同意、账单和支付流程，不应把一次授权当作未来周期都已完成的收费。确认业务规则、产品接口和支付方式支持后，再决定是否启用 capture_method=manual。

## 四、捕获期限不能一概而论

未捕获的 PaymentIntent 在一定期限后可能被自动取消或授权失效；Stripe API 文档说明，未捕获 PaymentIntent 默认通常在创建后一段时间取消，但具体时间会因支付方式和网络规则不同。对于部分卡片授权，PaymentIntent 或最新 Charge 可能提供 capture_before 等时间信息。应以每笔对象实际显示的期限为准，提前提醒履约系统完成决策。

不要把“7 天默认”视作所有卡、所有交易和所有国家的保证期限。延长授权需要支付方式、交易类型和账户满足相应条件，不能单靠商户数据库改一个日期实现。建立授权到期队列，及时捕获或取消；对接近期限的订单设置人工告警。若授权已过期或被取消，确认客户银行是否仍显示待处理，并按 Stripe 和银行记录继续查询，不要向客户承诺释放额度的精确时间。

## 五、如何捕获全部授权金额

只有处于可捕获状态的 PaymentIntent 才能执行捕获。默认情况下，若不传特定金额，捕获操作通常使用可捕获金额；但实现时仍要检查对象当前状态、amount_capturable、币种和业务订单金额。重复请求应考虑幂等性，并在请求结果后重新读取 PaymentIntent 状态，而不是仅依据 HTTP 请求成功就更新本地订单。

捕获成功后，更新内部状态为已捕获，记录捕获金额、时间、PaymentIntent ID、Charge ID和关联订单。如果请求失败，检查错误信息和对象状态，避免在状态变化后盲目重试。网络超时会让客户端不知道服务端是否已成功处理，应先通过 Stripe 对象查询结果确认是否已捕获，再决定重试。不要为了处理不确定响应而创建第二个 PaymentIntent。

## 六、部分捕获与剩余授权

有些业务最终金额低于原始授权金额，可能需要捕获较小金额。Stripe API 的 amount_to_capture 不能高于可捕获授权金额。剩余授权是否释放、能否继续捕获以及是否支持多次捕获，取决于具体支付方式和账户功能。Stripe API 还提供与多次捕获相关的参数，但不是所有账户或集成都可用。

在实现部分捕获前，确定商户是采用一次最终捕获并释放剩余金额，还是符合资格地保留余额并随后追加捕获。不要只根据 API 字段存在就假设账户支持多次捕获。将最终订单金额、授权金额、已捕获金额和未捕获余额分开记录，并在客户收据中呈现实际收费。若需额外金额，确认是否能在原授权内捕获、是否需要新的客户授权或新的付款流程，不要直接超过原金额。

## 七、如何取消未捕获的授权

若订单取消、库存不足或风控审核决定不履约，可能需要取消仍未捕获的 PaymentIntent，而不是创建一笔退款。退款适用于已捕获付款的资金返还；取消授权与退款是不同操作。先检查 PaymentIntent 状态和 amount_capturable，再通过 Stripe 支持的操作处理，并记录取消原因及对象 ID。

客户银行端的待处理记录何时消失，取决于发卡行的授权释放流程。商户可以向客户说明已在支付处理侧取消授权，并建议其通过发卡行查询具体显示时间，但不能保证当天消失。若授权已经捕获，就不能用取消未捕获付款的方式代替退款；应核实对象当前状态及是否已有退款。不要对同一笔交易同时执行捕获、取消和退款等互相冲突动作。

## 八、客户看到两笔相似记录怎么办

客户可能看到一笔待处理授权和一笔正式入账，或者多个付款尝试，其中一个成功、其他失败或取消。核对每一行记录对应的 PaymentIntent、Charge、金额、日期、状态和付款方式。不同银行会以各自方式显示授权、撤销和结算记录，因此截图中的两行并不一定代表两次已结算扣款。

客服应从商户后台查明实际是否存在一个或多个已捕获交易。若只有一笔成功捕获，向客户说明另一条记录是否为待处理授权，并建议其向银行确认释放流程；若确有重复捕获，按退款流程核对和处理。不要仅凭相同金额认定重复收费，也不要因为系统显示一个订单号就忽略存在两笔独立 Charge 的可能。

## 九、捕获失败的常见原因

捕获操作可能因 PaymentIntent 已不再处于 requires_capture、授权到期、捕获金额超过可用额度、付款方式不支持该操作、账户请求上下文错误或 API 参数不正确而失败。还可能出现网络超时，实际结果需要重新查询。查看 Stripe API 返回的错误类型、对象状态和最近事件，避免只把失败归因于“客户银行卡问题”。

对每个错误创建分类：状态不允许、授权金额不足、已取消或过期、账户/Connect 上下文不匹配、API 验证错误、暂时性网络错误。错误分类能指导是否需要联系客户、修改订单、尝试新的支付流程或升级支持。重试策略应区分暂时性错误与确定性错误，避免对已经过期的授权进行无限重试。

## 十、Webhook 和订单系统如何同步

手动捕获流程应监听与 PaymentIntent 状态变化相关的服务端事件，并将事件 ID、PaymentIntent ID、Charge ID和订单号保存到处理记录。收到 amount_capturable_updated 等提示后，系统可将订单放入“待捕获”队列；捕获操作完成后，根据更新后的对象或成功事件将订单改为“已捕获”。具体事件选择需查 Stripe 当前事件文档。

Webhook 可能重复或乱序，处理程序应具备幂等性，并在关键操作后重新读取对象权威状态。不要通过前端回跳参数把订单标记为已捕获。若事件显示捕获成功但本地订单仍待处理，按对象 ID进行补偿；若本地显示成功而 Stripe 对象仍未捕获，暂停履约并核查。保留授权到期、捕获结果、取消和退款的完整审计时间线。

## 十一、库存和风控审批的履约流程

如果手动捕获是为了确认库存，应及时锁定或预留商品，避免授权成功但审核期间库存已售罄。定义预留多久、库存何时释放、捕获失败后如何通知客户，以及取消后多久允许客户重新付款。没有明确规则时，客户可能看到待处理授权很久，而商户也难以判断是否应再次下单。

若业务要求风控人工审核，确保付款授权和审核决定都在有效窗口内处理。审核通过后先核实授权仍可捕获，再捕获和履约；审核拒绝或客户取消则取消未捕获授权。避免把 Radar Review 结果直接当作捕获结果。数字商品尤其要确认捕获成功后再开通权益，实体商品则需协调仓库和发货系统。人工和自动捕获同时运行时，必须有单一的订单状态锁定，防止双重操作。

## 十二、账单、收据和银行对账

授权记录、捕获金额、Balance Transaction 和 Payout 属于不同阶段。查看 Dashboard 时，确认客户授权金额与实际捕获金额是否相同，部分捕获是否有对应余额交易，银行 payout 是否包含该笔净额。捕获交易可能还要经过费用、余额可用期和 payout 批次，不能要求商户余额在捕获瞬间等于原授权金额。

客户收据应基于最终捕获金额生成。若先授权后捕获较少金额，更新订单小计、税费和费用信息，确保客户看到的账单与履约一致。使用部分捕获或多次捕获时，保存每次动作和最终合计，避免财务系统把每次捕获误当成独立订单。对账差异按 PaymentIntent 到 Balance Transaction 再到 Payout 路径逐层查找。

## 十三、设置监控与到期提醒

管理 manual capture 的关键指标包括待捕获授权数量、平均授权等待时间、接近到期的 PaymentIntent、捕获失败率、取消率、部分捕获订单、授权与捕获金额差异以及成功捕获后的履约延迟。只监控支付成功率会漏掉“授权已成功但从未捕获”的订单。

将 capture_before 或账户实际到期信息写入调度系统，在期限前分级提醒。若 Stripe 对特定支付方式的期限有变化，应以对象动态字段和官方文档更新规则，不要只依赖写死的固定天数。告警包含对象 ID、订单和负责人，不含秘密凭证或不必要的完整客户数据。定期抽查已过期授权，确认商户库存、订单状态与客户沟通均已闭环。

## 十四、常见场景与处理

### PaymentIntent 显示 requires_capture

核实订单金额、授权时间、付款方式和 capture_before 信息，决定按业务政策捕获或取消。客户银行卡上可能显示待处理授权，不要告知其已完成结算。

### 客户说已被扣款，商户却未收到钱

查对象是授权还是已捕获，再解释 Dashboard 的阶段和银行记录。若授权未捕获，说明目前资金处于授权流程；若已捕获，继续检查余额交易和 payout。

### 授权金额比最终订单高

检查是否为预授权、订单后来是否变更，以及当前支付方式允许的捕获方式。按实际授权和可捕获金额进行合规处理，不要试图捕获超过已授权金额。

### 捕获请求超时

先用 PaymentIntent ID 查询当前状态和 amount_received，再决定是否重试。不要立即创建另一笔付款。

### 客户取消，但银行仍显示待处理

确认 PaymentIntent 是否已取消、未捕获授权是否仍在银行端显示，并提供取消时间和交易参考。客户释放额度的时间需由发卡行确认。

### PaymentIntent 自动过期

检查捕获期限和失效原因。授权已经不能捕获时，依照业务流程重新向客户发起新的付款授权，而不是反复对旧对象操作；确保客户知道可能出现新的授权记录。

### 部分捕获后还需要收尾金额

先确认该 PaymentIntent 和账户是否支持后续捕获，以及原授权剩余金额和期限。若不支持，考虑新的、经客户授权的付款流程并清楚说明金额。

## 十五、生产环境安全检查清单

- 捕获前核实 PaymentIntent ID、订单和账户上下文
- 根据真实状态区分授权、捕获、取消和退款
- 核对 amount_capturable 与请求捕获金额
- 使用幂等请求和服务端状态查询处理网络重试
- 追踪 Stripe 实际提供的授权到期信息
- 监控待捕获队列和即将过期的对象
- 订单状态机区分待授权、待捕获、已捕获和已取消
- Webhook 处理具备重复事件和乱序保护
- 只有捕获成功后才执行相应履约
- 客户通知不承诺银行释放授权的精确时间
- 不在日志中保存 secret key、完整卡号或验证码

上线前在测试模式验证成功授权、完整捕获、部分捕获、取消、到期、API失败和Webhook重复等场景。真实支付方式的授权期限和行为可能与测试模拟不同，正式上线后继续监控实际对象数据。

## 常见问题

### 授权成功是不是代表付款成功？

授权代表发卡行批准了相应金额的预留，不等同于商户已捕获并完成收款。检查 PaymentIntent 的状态和捕获记录，再决定是否履约。

### 未捕获金额会自动退还吗？

未捕获授权的取消或到期处理取决于对象状态、支付方式和发卡行流程。商户应按 Stripe 状态处理，并让客户向银行核实待处理记录的释放时间。

### 可以捕获低于授权的金额吗？

对于支持的 PaymentIntent 捕获流程，可以在允许范围内指定金额，但需要核对 amount_capturable、支付方式和当前账户能力。剩余金额如何处理要遵循官方文档。

### 能不能捕获超过授权的金额？

捕获金额不能高于可捕获授权金额。需要额外收费时，应使用受支持且经客户同意的后续付款流程，不要将请求强行发送到 Stripe。

### 为什么银行显示扣了，但 Stripe 还没有 Payout？

银行展示可能是授权或待处理记录，而 Payout 是商户侧余额转出，二者是不同资金阶段。先查是否已捕获，再查 Balance Transaction 和 payout。

### Payment Link 支持手动捕获吗？

Payment Link 的 capture_method 配置和支付方式支持情况需按当前官方 Payment Link 文档核实。不要假设所有方式或现有链接都支持相同手动捕获能力。

## 总结

Stripe 手动捕获流程先授权，再由商户在期限内决定捕获或取消。授权状态不等于已结算收款，客户看到的银行待处理记录也不等于 Payout。排查时以 PaymentIntent ID、requires_capture、amount_capturable、对象时间线和 capture_before 等信息为依据，使用幂等操作并在捕获后再履约。授权有效期因支付方式和网络而异，应按实际交易信息管理。
