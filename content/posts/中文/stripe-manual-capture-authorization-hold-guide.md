# Stripe 预授权和手动捕获是什么？商家延迟扣款的操作指南

有些商家不会在客户下单时立刻确认发货，例如需要先核对库存、预订房间、确认服务时间或检查订单风险。这时，支付流程可能采用“先授权、后捕获”：客户付款方式先通过发卡机构授权，商家之后再决定是否实际完成扣款。在 Stripe 中，这类做法通常称为手动捕获或分别授权与捕获。

它与普通的自动捕获不同。自动捕获会在客户授权后自动完成收款流程；手动捕获则先对资金做授权，待商家准备好后再发起捕获。授权成功不等于商家已经收到可用款项，也不等于交易永远不会过期。不同支付方式是否支持手动捕获、授权有效时长和账户可用操作都有差异，必须查看 Stripe Dashboard 和对应付款方式的官方文档。

## 授权、捕获和结算分别是什么？

授权是客户的银行或发卡机构批准一笔支付请求，并可能暂时占用持卡人的可用额度。授权阶段会向商家返回成功或失败结果。对客户而言，银行账户可能显示一笔待处理交易或额度减少；对商家而言，支付对象则可能处于等待捕获的状态。

捕获是商家向支付处理方请求完成已授权的付款。商家捕获后，支付流程继续进入后续处理。若商家只捕获部分金额，能否这样操作及可捕获金额限制取决于账户、支付方式和相关配置。Stripe 的 Capture PaymentIntent API 说明，捕获对象必须处于可捕获状态，且捕获金额不能超过原始授权金额。不要将“捕获”理解为银行已经把钱汇到商家的银行账户。

结算和打款又是后续阶段。客户的付款完成后，资金仍可能经过 Stripe 余额可用时间、打款排期和银行处理。因此，如果关注的是商家何时在银行收到资金，还需要区分支付捕获、余额可用和账户打款等时间线。

## 自动捕获和手动捕获有什么区别？

自动捕获更适合客户下单后立即确认并履行的流程。顾客完成支付授权后，Stripe 按配置继续完成收款步骤，商家无需再逐笔判断是否捕获。普通在线零售、数字产品即时交付等场景常采用这种流程，具体仍需以商家使用的 Checkout、Payment Links 或 API 配置为准。

手动捕获适合履约确认发生在支付授权之后的场景。例如，商家要先确认库存、最终价格、物流安排或预约可用性。商家可以先请求授权，等确认条件满足后再捕获。在库存不足、订单存在异常或顾客取消的情况下，商家可能选择不捕获并取消授权，具体操作要根据支付状态及账户支持情况处理。

手动捕获会增加运营责任。商家必须记录每一笔等待捕获的支付，安排负责人定期检查，并在授权有效期内完成捕获或取消。若只开启手动捕获，却没有订单队列、提醒和失败重试流程，订单可能长期停留在待处理状态，顾客会认为付款失败或银行卡被重复扣款。

## 为什么客户银行显示扣款，但商家还没有收到钱？

当支付处于授权阶段，客户银行可能显示待处理扣款或额度占用。这通常不等于已经完成一笔最终结算，也不一定意味着商家的 Stripe 余额已经增加。持卡人的银行界面可能把授权显示成“待处理”“预授权”或类似描述，具体措辞由发卡机构决定。

若商家后来捕获支付，银行会继续处理这笔授权。若商家取消授权或授权过期，银行之后可能释放被占用的额度。释放时间取决于发卡机构和当地支付网络，商家通常无法通过 Stripe Dashboard 直接加速银行更新。客户短时间内看到待处理记录仍在，并不一定意味着商家重复扣款。

如果订单页面显示付款成功但 Stripe Dashboard 状态为待捕获，商家要避免把它当作已收款订单发货。先确认支付对象状态与订单系统同步逻辑，再决定是否履约。若订单状态和 Stripe 状态不一致，按 PaymentIntent 或 Charge 等标识核对，不能只靠客户截屏或订单金额判断。

## 哪些情况适合使用手动捕获？

第一类是需要确认库存或可售数量的业务。商家可能希望在确认商品可发货后才最终完成扣款。不过要仔细规划授权额度和商品价格，特别是订单总额可能因运费、税费或替代商品调整的情况。只有支付方式和账户配置支持时，才可以根据实际业务流程使用相关捕获方式。

第二类是住宿、租赁或预约服务。商家可能在服务实际提供之前先授权，以确保客户具备支付能力，然后按约定时间捕获款项。必须把商家条款、授权时间、取消政策和最终收费说明清楚，并遵守适用的支付网络和消费者保护规则。不能把预授权当作无限期冻结资金的手段。

第三类是商家需要审核订单或风险信息的流程。授权后，商家可以根据自己的风险政策确认订单是否履约。但拒绝交易时，仍要及时取消授权，并向客户提供准确说明。不要让客户长时间等待不明确的支付状态。

手动捕获不适合没有监控机制的业务。若团队无法及时检查授权期限，自动捕获往往更简单。手动模式也不能解决退款、争议或欺诈问题；商家仍需维护清晰的客户沟通、配送证明和订单风险审核流程。

## 未捕获的授权会怎样？

未捕获支付可能在一段时间后失效、取消或需要重新授权。Stripe 的 API 文档指出，未捕获的 PaymentIntent 会在一定天数后取消，默认描述为创建后 7 天；但实际授权期限可能受支付方式、网络规则和具体账户情况影响，不能将这个默认值理解为所有银行卡和业务都固定相同。

授权到期之后，商家可能无法直接捕获原支付，需要联系客户重新完成付款。客户也可能已经看到银行中的待处理记录，担心商家扣款失败或重复收费。商家应在订单系统中监控待捕获订单和授权到期时间，在临近期限前通知相关团队处理。

不要因为在 API 文档中看到一个默认天数，就把它硬编码为对所有支付方式通用的期限。根据账户 Dashboard 中的捕获期限、Stripe 返回的信息和实际 PaymentIntent 数据确定当前交易的状态。如果支持捕获截止时间或其它支付详情字段，应以对应对象值和官方集成文档为准。

## 商家如何捕获或取消付款？

若使用 Stripe Dashboard，进入相应支付详情查看当前状态和可用操作。如果页面提供“捕获”或“取消授权”选项，确认客户、订单、金额、币种和库存后再操作。捕获后再次查看交易是否进入预期状态，并确认订单系统同步更新；取消后确认订单没有继续被标记为已付款。

若通过 API 集成，应遵循 Stripe PaymentIntents 的捕获流程。只有处于可捕获状态的支付才能执行捕获。捕获金额不得超过该支付可捕获金额；部分捕获能力和后续捕获方式受具体配置影响。保存支付对象 ID、请求时间、响应状态和失败原因，以便在网络超时或后台状态延迟时排查。

对于异步系统，应使用幂等请求设计和状态同步机制，避免调用超时后重复发起操作。重试之前先检索原 PaymentIntent 状态，确认之前的请求是否已经成功。不要将 API 密钥放在浏览器端、公开代码或 GitHub 页面中；服务器环境变量和密钥权限应按 Stripe 官方安全建议管理。

## 如何处理部分捕获和订单金额变化？

订单金额发生变化时，先确认原授权金额、可捕获金额及账户支持的捕获方式。若最终金额低于授权金额，某些流程可以捕获较少金额；未捕获部分如何释放及是否支持额外捕获，要看支付方式和 Stripe 功能。若最终金额高于授权金额，不要擅自认为可以捕获更多。可能需要重新授权、使用额外付款流程或采用业务允许的处理方式。

在商品部分发货、电商拆单或服务分期交付场景中，商家还要确认是否支持多次捕获。不能默认所有银行卡、账户和集成都支持多次捕获。将用户看到的总价和实际捕获金额对应到订单项目，并在收据或订单详情中保留清晰说明，减少顾客把部分捕获误解为重复扣款。

对于金额调整和额外收费，提前在结账页和服务条款中解释可能产生的费用。若客户没有授权额外金额，不能把支付技术能力当作对消费者收费的许可。业务规则和法律义务应单独评估。

## 顾客说被扣款，商家该怎么解释？

先核对 Stripe 中该笔支付是否为授权、已捕获、已取消或失败，再确认订单系统是否记录了相同的支付 ID。若仅为授权，向顾客说明这可能是银行卡的待处理额度占用，并告知商家还没有确认最终捕获；不要承诺具体的银行释放日期。

若商家已经取消或授权过期，说明已在支付平台执行取消或释放操作，并建议顾客联系发卡银行查询待处理记录何时更新。提供交易时间、金额和币种等非敏感信息即可。不要让客户发送完整卡号、安全码、银行密码或短信验证码。

若 Stripe 显示支付已捕获，而顾客认为被重复扣款，查看是否存在多笔 PaymentIntent、不同订单尝试、授权加捕获两类记录，或银行重复展示同一笔授权与已捕获交易。向顾客解释前应先确保交易 ID 和金额一一对应，必要时向 Stripe 支持提供对象 ID 进一步核查。

## 常见问题

### 手动捕获是否代表客户已经付款？

不代表最终扣款已完成。授权表示发卡机构批准并可能临时占用额度；商家还需要按流程捕获，之后资金才进入支付处理和结算阶段。

### Stripe 手动捕获后，客户多久看到正式扣款？

客户银行显示时间由发卡机构和支付网络处理，可能与 Stripe 状态更新时刻不同。查看具体支付状态，并避免承诺固定到账时间。

### 取消授权后，客户为什么还看到待处理交易？

银行可能需要时间更新授权和可用额度。商家可以确认 Stripe 已执行取消操作，再让客户联系发卡行查询银行端的释放时间。

### 所有支付方式都支持手动捕获吗？

不是。Stripe 官方资料明确指出，并非所有支付方式都支持手动捕获。商家应查询自己的国家/地区、支付方式和集成方式对应的文档及 Dashboard 选项。

### 授权过期以后还能直接捕获吗？

要看支付对象当前状态和具体支付方式。未捕获的 PaymentIntent 可能被取消；如果已不能捕获，商家通常需要重新向客户请求付款，而不是反复调用捕获接口。

## 总结

Stripe 手动捕获允许商家先取得支付授权，确认履约条件后再捕获资金。它能匹配需要核对库存、预约或订单审核的流程，但会增加订单监控和客户沟通责任。商家要明确区分授权、捕获、余额可用和银行打款，跟踪每笔待捕获交易，并根据实际支付方式和 Dashboard 状态行动。客户银行显示暂挂额度时，应准确解释当前阶段，不要把预授权说成已完成收款，也不要重复创建付款。

*本文依据 Stripe 官方文档整理；手动捕获支持范围、授权期限和捕获行为可能因支付方式、账户地区和集成配置而异。*
