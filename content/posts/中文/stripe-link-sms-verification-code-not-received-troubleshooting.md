# Stripe Link 收不到短信验证码怎么办？邮箱验证、设备与测试环境排查

使用 Stripe Link 快速结账时，用户可能输入邮箱后需要通过短信或邮件一次性验证码确认身份。如果验证码迟迟没到，付款流程就卡在登录或自动填入付款资料之前。用户可能反复点“重发”，甚至以为商家收不到付款，转而在同一订单上重新结账。

Link 是 Stripe 提供的数字钱包与快速结账服务。Link 官方帮助资料说明，用户在新网站、新设备或浏览器上使用 Link 时，可能会通过手机或邮箱接收验证码验证身份。验证码用于确认 Link 账户，不是银行卡交易密码，也不应该发给商家客服。是否需要短信、邮箱或其他验证方式会因设备、账户和当前结账流程不同而变化。

本文按“确认验证码类型、检查手机和邮箱、区分测试环境、保护账户”的顺序排查。还会说明为什么意外收到 Stripe/Link 验证短信，不一定意味着已经发生扣款。不要将 Link 验证码与商家登录 Stripe Dashboard 的两步验证混为一谈。

## 先确认这是 Link 验证还是 Stripe 商家登录验证

Stripe 和 Link 有不同类型的验证码。Link 结账验证码通常用于消费者登录或验证保存的付款信息；Stripe Dashboard 短信验证码则用于商家或团队成员登录 Stripe 管理后台。两个流程的用途、账户和恢复方式不同。确认页面是商家结账中的 Link 登录、Link 账户网站，还是 Stripe 商家 Dashboard 后，再按相应流程处理。

如果页面显示你的邮箱、Link 标志或保存的卡片资料，通常属于消费者 Link 验证。若你正在登录 Stripe 商家 Dashboard，并要求团队账号的两步验证，则应通过 Stripe 用户资料里的安全设置、备用验证码或认证器处理。不要把商家 Dashboard 的帮助步骤用于消费者 Link 结账，也不要要求商家客服代替你完成验证码验证。

核对网址和发起来源。通过商家官网开始付款，确认跳转到 Link 或 Stripe 支持的安全页面；不要从陌生短信、邮件或社交媒体消息中的链接输入验证码。Stripe/Link 验证码用于本人完成当前操作，不应转发给任何人，包括自称 Stripe、银行或商家的客服。

## 检查手机号、国家码和账户邮箱

首先确认 Link 账户绑定的手机号码仍是你可以接收短信的号码。旧号码、停用 SIM 卡、换号、漫游、双卡设置或国家代码填写错误，都可能让短信无法到达。若 Link 账户的邮箱也发生变化，检查当前结账输入的邮箱是否对应保存付款资料时使用的邮箱。Link 会将付款信息与邮箱和手机号码关联，使用另一个邮箱可能进入不同的验证流程或新账户流程。

如果刚换过手机号，不能保证仅在当前结账页改号码就会更新 Link 账户资料。登录 Link 官方账户后查看账户设置与验证选项，按页面的账户恢复流程更新。如果无法访问旧号码，使用 Link 官方帮助入口联系支持，核验身份并询问可用的替代方式。不要向商家客服发送身份证件或完整支付信息，除非商家提供了明确且安全的上传渠道。

若手机使用双卡或漫游，确认接收短信的 SIM 已启用，运营商短信服务正常，短码或国际短信没有被拦截。可以检查垃圾短信或拦截列表，并确认设备未启用会自动屏蔽服务类短信的设置。验证码可能由不同短信通道发送，手机信号、运营商路由和漫游策略都可能影响送达。

## 短信没有到时按顺序排查

先等待当前页面提示的时间。不要在很短时间内连续请求多次新码；旧码可能因此失效，后到的短信也可能包含比先前更早的验证码。若验证码晚到，先确认页面输入框仍对应最新请求，并按页面错误提示处理。

检查手机信号、飞行模式、短信收件箱空间和运营商拦截设置。重启手机或重新连接移动网络后再尝试一次。若你正在使用 VoIP、虚拟号码、企业短信网关或只接受本地短信的号码，可能无法接收该服务的验证码；使用账户支持的真实手机号，或在页面提供时选择邮箱验证码。

如果页面提供“通过邮件验证”或“发送到其他方式”，可选择与你 Link 账户绑定并能访问的方式。不要把验证码转发给其他人。若没有替代方式，联系 Link 官方支持或从商家官网的支持入口询问是否可以重新启动验证流程。商家通常无法读取或代替客户输入消费者 Link 验证码。

若在多个设备上尝试，记住新设备本身可能触发身份验证。尽量使用常用设备和浏览器完成付款，并确保浏览器允许结账流程正常运行。切换设备、浏览器和网络不一定能绕过验证，反而可能触发更多安全检查。

## 邮件验证码也没有收到怎么办

若页面允许通过电子邮件验证，先核对当前输入的邮箱是否为 Link 账户邮箱。查看垃圾邮件、社交、促销、更新等分类，以及收件规则、自动归档、转发和企业邮件隔离区。公司邮箱可能由第三方安全网关拦截；联系企业 IT 检查邮件服务商是否阻止了来自 Link 或 Stripe 的验证邮件。

邮箱搜索 Link、Stripe、verification 或近期登录时间，确认是否有邮件被自动移动。确保邮箱可正常收信且没有容量限制。若页面可以重新发送，等待页面规定时间后只请求一次，并使用最新收到的链接或验证码。验证邮件的链接可能短期有效，过期后应从官方登录流程重新申请。

若你不再访问原邮箱，先通过 Link 官方账户恢复流程更新账户邮箱，而不是在付款页面连续尝试多个地址。不同邮箱可能分别绑定不同的 Link 账户和订单历史。核对订单时通过商家官网使用购买邮箱或订单编号，避免因邮箱不同误认为付款或订阅记录丢失。

## Link 测试环境为什么不会收到真实短信

开发者在 Stripe Test mode 或 Sandbox 测试 Link 时，可能期待收到真实六位短信验证码，但测试环境通常使用官方文档提供的模拟验证码，而不是向真实手机发送一次性短信。Stripe 官方集成帮助资料明确说明，在 Payment Element 的测试场景中，用户不会收到真实的 Link 六位短信验证码，应使用 Link 测试指南列出的测试验证码。

如果你是开发者，先确认 Checkout、Payment Element、Publishable key 和 Dashboard 当前处于测试环境，再按 Stripe 最新 Link 测试文档进行认证。不要把生产用户的真实验证码输入到测试项目，也不要以“短信没到”判断测试集成损坏。测试成功后，正式环境仍需验证实际手机和邮箱流程，但不要使用真实客户资料进行未经授权的测试。

测试 Link 的 PaymentIntent、客户和事件对象也与 Live mode 分开。若测试邮箱没收到生产收据、或生产 Dashboard 看不到测试对象，应先检查模式与账户，而非重复创建订单。上线时确认生产 Link 配置、网站域名和商家结账流程正确，并仅在真实客户授权下使用其付款资料。

## 意外收到 Stripe/Link 验证短信怎么办

有时用户会收到“Your Stripe verification code is ...”短信，却没有主动购买或登录。Stripe 官方帮助说明，这可能是有人在使用 Link 时错误输入了你的手机号码，也可能是你在其他设备上使用过 Link、当前设备被记住或触发了周期验证。单独收到验证码不等于支付已成功，也不能据此认定银行卡被盗。

如果你没有发起当前操作，不要将验证码发给任何人，也不要点短信中的陌生链接。查看 Link 账户的 Activity 或购买记录；若不认识任何活动，登录 Link 官方网站检查账户、设备和保存的付款方式。Link 帮助中心建议，用户若怀疑账户在其他设备上处于登录状态，可采取退出其他设备等措施。

若短信频繁出现，确认手机号码是否被误用于其他人的 Link 账户；可联系 Link 官方支持或查看其管理短信的页面。若 Link 账户中发现未经本人授权的付款，立即联系商家和发卡银行，按实际情况处理。不要因为一条验证码短信直接向陌生人报出卡片信息。


## 手机号码被其他人误填时

如果你没有使用 Link、也没有尝试付款，但收到一条验证码短信，先不要回复验证码或联系短信中的陌生号码。Stripe 官方说明，可能有人在 Link 结账时输入了自己的电话号码错误。验证码未被提供给对方之前，对方通常无法仅凭短信完成你的手机号验证，但你仍应避免将其告知任何人。

检查短信内容是否只是一次性验证码，还是包含可疑的退款、账户冻结或链接。真实验证码只用于本人完成当前 Link 流程；任何人索要它都应视为异常。若你担心手机号与 Link 账户绑定错误，可通过 Link 官方账户设置和支持渠道核查，并按说明移除或更新保存的联系方式。

若短信持续重复出现，记录大致时间和频率，联系运营商查询是否有号码转发或短信异常，并通过 Link 官方渠道说明情况。不要在公开渠道发出完整手机号、短信截图或验证码。

## 如何区分验证码失败与付款失败

验证未完成通常表示用户还没有通过 Link 身份检查或未进入付款授权步骤。它不自动代表商家已收费，也不一定会产生付款交易。相反，用户已完成身份验证并点击确认后，银行卡或银行账户支付仍可能被拒绝、处理中或成功。应查看商家订单状态、收据、银行记录和 Stripe 支付页面的实际结果。

若验证码成功后页面卡住，先返回商家订单确认是否已经创建付款。不要马上重复点击“Pay”或重新创建另一个订单。若 Stripe 交易状态不明确，由商家检查 PaymentIntent 或 Checkout Session，确认是否存在成功、待处理或失败的付款。消费者没有商家 Dashboard 权限，需让商家按订单号和时间核对。

Link 验证和付款授权是不同步骤。客户成功通过短信验证，不代表商家已收到款；同样，付款失败也不表示 Link 账户验证失败。联系支持时说明页面提示出现在何时、是否完成支付按钮、有没有订单号和银行记录，不要只说“Stripe 验证码坏了”。

## 客服和开发者可以做什么

开发人员应只收集排错所需的匿名化数据，不收验证码和密码。

商家客服可确认客户输入的邮箱是否对应订单、结账是否使用 Link、页面是否提供邮件验证或其他方式，并查看支付对象是否创建。客服不能查看客户验证码或代为通过 Link 身份验证。若客户报告短信延迟，建议其检查运营商、短信拦截、邮箱和账户号码，通过官方支持入口继续处理。

集成开发者应确认 Link 是否在当前 Payment Element、Checkout 或 Payment Request Button 流程中启用，并按 Stripe 测试文档验证模拟代码。记录请求 ID、Session ID、错误码、测试或实时模式和前端错误；不要在日志中记录验证码、完整卡号或用户银行凭据。若问题仅发生于个别运营商或国家，提供匿名化的环境信息向 Stripe 支持咨询。

若商家不希望提供 Link 快速结账，可在其支持的范围内调整支付方式设置，但应确认其他卡支付流程仍然可用。客户若不想使用 Link，可以询问商家是否有直接卡片付款或其他正规方式；不要要求用户绕过安全验证或共享账户。

## 常见问题

### Link 验证码一般多久能到？

送达时间受运营商、网络和当前身份验证流程影响。按页面提示等待后再请求新码，避免连续点重发。若延迟持续，检查号码、信号和短信拦截，或使用页面提供的邮箱验证方式。

### 我收到了短信，但我没有使用 Link，是盗刷吗？

未必。可能是别人误填了你的号码，或之前的 Link 设备触发了验证。不要分享验证码，检查 Link 活动和银行账户；确认存在未经授权交易时再联系商家和银行。

### 测试模式下为什么手机没有收到 Link 验证码？

测试集成通常使用 Stripe 文档列出的模拟验证码，不发送真实短信。确认项目处于测试环境，并使用当前官方 Link 测试指南的代码。

### 商家能替我输入验证码吗？

不能。验证码应由账户持有人在 Link 官方验证页面输入。不要通过客服、邮件或社交媒体把验证码告诉任何人。

### 收不到 Link 短信能否改用银行卡直接付款？

是否支持取决于商家结账页。查看页面有没有其他支付选项，或联系商家确认。切换方式前先确认 Link 流程没有已经创建或成功的付款，避免重复收费。

## 总结

Stripe Link 短信验证码用于验证消费者身份，常在新设备或浏览器上使用保存的付款资料时出现。收不到时，先确认邮箱和手机号、检查信号和拦截设置、等待后再请求最新验证码，并使用页面提供的邮箱方式或官方账户恢复流程。测试环境通常使用模拟验证码，不会发送真实短信。未主动请求的验证码不要转发，检查 Link 活动和账户安全。Link 验证成功不等于支付成功，最终以商家订单、Stripe 交易状态和银行记录为准。
