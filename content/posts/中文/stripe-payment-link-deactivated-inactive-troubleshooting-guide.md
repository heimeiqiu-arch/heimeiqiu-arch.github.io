# Stripe Payment Link 显示已停用怎么办？链接失效排查与重新发布

打开商家发来的 Stripe Payment Link 后，如果页面显示链接已停用、无法付款或商品不可用，买家通常不知道是链接写错、订单过期，还是商家已经停止销售。商家也可能在更新价格、结束活动或清理旧页面后，发现原来的二维码和社交媒体链接全部失效。排查时要先确认具体对象：Stripe Payment Link 是一个可分享的付款页面链接，不等同于发票链接、Checkout Session 或网站上的自建订单页。

Stripe 的 Payment Link 对象包含 active 状态。官方 API 参考指出，如果 active 为 false，访问其 URL 的客户会看到该链接已停用的页面。Stripe 帮助资料也说明，Payment Links 通常不会因时间经过自动失效，除非商家将其停用。因此，遇到“链接过期”字样时，不要直接假定所有 Payment Links 都有统一到期时间，也不要把停用链接和尚未付款的发票混为一谈。

本文从买家与商家两方面说明，如何核对链接、检查 Payment Link 状态、确认商品价格和账户配置，以及在修复后安全重新分享。Stripe Dashboard、产品功能和账号资格可能随账户地区与版本变化，实际操作以当前登录的 Stripe 官方账户和文档为准。

## 先确认链接类型和页面提示

先检查链接来源和域名。商家可以通过 Stripe Payment Links 分享固定价格商品、订阅或按客户自选金额付款；也可以使用 Stripe Invoice 的托管付款页面或一次性 Checkout Session。它们的页面外观可能相似，但底层对象与管理入口不同。Payment Link 通常是可重复分享的 URL；单笔发票链接则关联一张具体发票，Checkout Session 则关联一次结账流程。

从商家后台创建链接时，找到 Payment Links 列表，核对链接名称、URL、商品、价格、创建时间和 active 状态。买家可以把页面完整地址和错误提示发给商家，但应隐藏订单中不必要的个人信息。不要仅凭“付款页面打不开”就判断 Stripe 服务故障，也不要使用搜索到的第三方“修复链接”网站提交卡片资料。

如果链接来自短信、社交媒体私信或邮件，先从商家官网核对销售页面或官方联系方式。钓鱼者也可能模仿 Stripe hosted page，因此请确认该链接确实由你购买的商家发出。Stripe 作为支付服务商并不自动证明销售方身份；商品和退款问题仍要向实际商家核实。

## 买家打开链接后无法付款怎么办

买家首先可以确认链接是否完整，尤其是从聊天软件复制时，链接末尾参数可能被截断，或者换行字符破坏了地址。尽量让商家重新发送官方付款链接，不要自行猜测短网址原地址。如果链接显示停用，应联系商家确认商品是否仍在销售、当前价格是否变化，以及商家是否可以发送新的付款链接。

如果商家确认链接有效，但你仍看不到付款页面，可以在不重复提交付款的前提下尝试更新浏览器、从商家官网重新打开，或使用另一款受支持的浏览器对照。检查浏览器是否拦截了页面脚本、Cookie 或重定向，但不要为了付款关闭系统安全保护。公司代理、防火墙或网络访问限制也可能影响托管页面加载；可以换用可信网络测试，再由商家确认实际页面状态。

如果页面可打开但付款失败，应区分“Payment Link 未激活”和“卡片付款被拒绝”。停用链接时，错误重点在链接状态；卡片被拒绝则通常发生在提交支付后。不要多次快速点击付款按钮或反复创建订单。先检查 Stripe 收据、商家确认邮件和银行卡待处理记录，确认是否已生成交易。若已付款但未收到商家确认，请提供付款时间、金额和订单信息给商家核对，而不是在旧链接上再付一次。

买家不应向任何人发送完整卡号、安全码、银行密码、PayPal 密码或短信验证码。商家若需要核对订单，通常可通过订单号、Stripe 交易参考和支付时间完成。若收到付款链接但不认识商品或商家，应暂停交易并通过自己输入的官方域名联系商家。

## 商家在 Dashboard 里怎样检查 active 状态

商家应登录 Stripe Dashboard，并切换到正确的账户和模式。Stripe 区分测试数据与实时数据；在测试模式创建的 Payment Link 不应被当成真实收款链接分享。若使用 Connect 或多个业务账户，也要确认当前 Dashboard 选择了创建链接的正确账户。模式或账户选错，会让管理员误以为链接不存在或状态不一致。

进入 Payment Links 列表后，根据链接名称、商品或创建时间定位对象，打开详情确认它是否处于 active 状态。Stripe 的 Payment Link 对象会记录 URL 和 active 值；停用时，客户访问 URL 会看到链接已被停用。若仪表板页面提示与买家截图不一致，核对账户、测试或实时模式、链接 ID 和 URL 是否完全匹配。

检查时不要只看列表中的标题。商家可能有多个近似名称的产品，例如月付和年付套餐、测试款和正式款、旧价格和新价格。打开具体链接详情，核对 line items（商品项目）、数量、金额、币种、一次性或订阅模式、税费和成功后跳转配置。确认当前 URL 指向预期商品后，再判断是恢复原链接还是创建新链接。

如果团队成员近期停用了链接，查看内部变更记录或沟通记录，了解是否属于活动结束、价格更新、库存不足或误操作。某些停用可能是有意的，比如旧活动价不再有效；直接重新启用可能会让旧客户继续按错误价格付款。先确认业务政策和当前商品信息，再决定恢复还是替换。

## 链接被停用时如何处理

如果商品、价格、条款和销售资格都没有变化，且团队确定原链接应继续使用，可以在 Dashboard 中检查该 Payment Link 的管理选项是否允许重新激活。可用操作可能因当前产品版本和对象状态而异；根据页面提示恢复，并保存链接状态与更新时间。完成后，用商家自己的测试流程验证页面能否正确打开、商品和金额是否准确。

如果原价格、商品内容或条款已经变化，通常应仔细评估是否需要创建新的 Payment Link，而不是重新启用旧链接。新的链接可以更清晰地区分新旧销售条件，减少客户根据旧社交媒体帖子支付过期价格的风险。对于订阅产品，检查周期、试用期、续费金额、取消政策和税务设置；对于一次性产品，核对库存、数量、描述和售后说明。

更新链接后，维护所有分享入口。网站按钮、二维码、社交媒体简介、广告素材、邮件模板和客服话术可能仍指向旧 URL。建立一个替换清单，逐处更新并由第二人抽查。若短网址服务将旧地址重定向到新链接，确认域名仍由商家控制，且没有跳转到第三方不可信页面。

Stripe Payment Links 的 URL 通常可以重复分享，并不代表商家必须长期保持它有效。活动结束后，商家可以停用链接，并在产品页面说明活动时间或停止销售日期。若链接被意外停用，先确认停用原因再恢复；如果链接包含旧价格或旧条款，应更新相关页面并重新发送正式入口。

## 检查商品、价格和销售配置

有时买家描述的是“链接无效”，实际是付款页面加载后发现商品不能购买、金额不符或选项无法选择。这时要核对商品对象及价格是否仍可用于创建 Payment Link，商品是否被存档或改价，价格币种是否符合预期，数量选择和可选金额设置是否正确。Stripe Dashboard 可能允许更改链接商品和价格配置，但不同修改对既有链接和已支付订单的影响需要按当前文档确认。

如果是客户自选金额链接，确认设置的最低金额、最高金额和默认金额是否合理。Stripe 的 Payment Links 可配置客户选择付款金额的场景，但具体支持的付款类型、货币与功能受产品设置限制。不要把“页面允许客户输入金额”误解成可以接受任意负数、任意币种或全部支付方式。

若链接用于订阅，确保周期价格和计费行为准确。买家可能看到页面显示月度或年度的重复付款；要清楚说明试用和续费。不要只修复 active 状态，却遗漏原链接使用的旧订阅价格或错误试用天数。上线前用测试模式检查付款完成页、账单邮件和商家系统中的订阅状态，并在可行情况下由团队成员复核。

如果商品明明正常但创建或更新链接失败，检查账户权限、Dashboard 提示、网络状态和账号当前限制。不是所有故障都能通过复制 URL 解决。需要与 Stripe 支持沟通时，准备 Payment Link ID、账户模式、操作时间、错误截图和相关 Dashboard 页面，并遮挡 API secret、客户卡片信息等敏感字段。

## Payment Link 和 Invoice 链接有什么区别

Payment Link 主要用于创建一个可重复使用和分享的付款页面；商家可以把它放在网站、邮件、社交媒体或二维码中，接受多位客户付款，具体配置决定对应商品和付款方式。Stripe 官方帮助资料指出，Payment Links 通常不会自动过期，商家可以停用链接来结束其可用性。

Invoice（发票）是面向特定客户和账单的记录，可能对应特定金额、付款期限、客户、订阅或服务。托管发票页通常服务于这张发票，账单状态可能是 draft、open、paid、void 或其他状态。发票链接不能简单当作所有客户通用的付款页。若客户说“Stripe 发票链接过期”，应检查发票自身状态、到期日和是否重新发送，而不是仅去 Payment Links 列表找同一对象。

Checkout Session 则是某次结账流程的会话对象，可能因使用场景或配置在一段时间后不再可用。重新创建会话和停用 Payment Link 是不同操作。先辨认链接来源、URL 类型和 Dashboard 对象，再按照对应产品处理，能够避免重发错误链接或让客户支付了不应继续销售的旧商品。

## 上线、分享与复核流程

商家正式分享新链接前，建议按以下顺序检查：

1. 确认当前账户、地区和测试或实时模式。
2. 核对 Payment Link 对应的商品、币种、价格、数量和付款模式。
3. 检查链接 active 状态及成功后的客户说明。
4. 使用团队批准的测试方法验证页面，而不是让客户替商家试错。
5. 检查收款后的订单、收据和履约流程能否正确关联。
6. 更新官网、二维码、社交媒体、邮件模板及客服资料。
7. 保存链接 ID、用途、负责人、创建日期和停用条件。

对外页面要明确写出商家身份、商品服务内容、支付金额、一次性或定期付款、交付方式、联系渠道和退款条款。付款链接页面无法替代完整的销售说明。客户如果只看到价格，不清楚买到什么、何时交付或怎样续订，容易产生退款申请和争议。

分享收款链接时，按最小必要范围分发。对于只应给某位客户使用的收款请求，使用对应客户的发票或其他合适产品，而不是把通用 Payment Link 当成私密链接。Payment Link URL 被转发后可能被其他人打开；商家需要核对产品设计是否适合广泛分享，并为履约配置订单和数量管理。


## 客服处理时应保留哪些信息

无论是买家还是商家，排查支付链接问题都应保存最小必要的上下文。包括 Payment Link 的完整 URL 或链接 ID、页面提示、访问时间和所在时区、使用测试或实时环境、关联商品名称以及是否已经尝试提交付款。商家还可记录是谁创建或停用了链接、变更发生时间和业务原因。买家应避免公开分享包含个人邮箱、账单地址或订单明细的完整截图；将必要信息通过商家官网的安全支持渠道提供即可。记录清楚以后，支持人员更容易区分是旧链接、账户选择错误、商品状态变化还是一次具体的交易失败，也能减少客服让用户重复尝试付款的风险。

## 常见问题

### Stripe Payment Link 会自动过期吗？

Stripe 官方帮助资料说明，Payment Links 通常不会因为经过固定天数而自动失效，除非商家将其停用。但这不等于所有链接永远有效；商家可停用链接，也可能因为商品销售策略或账户配置而更改可用性。检查具体 Payment Link 的 active 状态和 Dashboard 说明。

### 链接页面提示已停用，买家能自行修复吗？

通常不行。买家无法修改商家 Stripe 账户里的 Payment Link 状态。应联系实际商家，请其确认商品仍在售，并发送经核对的新链接。不要用第三方站点改写或“激活”支付链接。

### 原链接恢复后还可以继续分享吗？

若商家确认商品、价格、销售条款和库存仍准确，并且 Dashboard 提供恢复操作，可以按当前账户流程处理。恢复前要确认停用原因；如旧价格已过期，创建新链接并更新外部页面可能更稳妥。

### Payment Link 和发票付款链接是同一个吗？

不是。Payment Link 一般是分享式的商品付款页面；Invoice 链接关联具体发票和账单状态。先在 Dashboard 找到对应对象，再按其类型处理。重发一条通用 Payment Link 不一定能解决已关闭的特定发票。

### 买家已经支付但商家没看到订单怎么办？

先让买家保留 Stripe 收据或支付参考，不要再次付款。商家检查 Stripe Dashboard 中的付款对象、Payment Link 关联信息和自己的订单系统是否同步。订单同步延迟或 webhook 处理失败需要商家核对，不应要求买家把完整卡片信息发来。

## 总结

Stripe Payment Link 提示停用时，先确认这是 Payment Link，而不是 Invoice 或 Checkout Session；然后从正确的 Stripe 账户和模式检查链接的 active 状态、商品配置和停用原因。商品和条款未变且 Dashboard 允许时，商家可以考虑恢复原链接；价格或销售规则已经变化时，应创建新链接并更新所有二维码、网页和推广内容。买家无法自行恢复商家端链接状态，应通过商家官方渠道索取新的付款入口，并在不确定是否已经付款时先核对交易，避免重复支付。
