商户在 Stripe Dashboard 点击退款后，客户不一定会立刻在银行卡流水中看到一笔新的入账。有时 Stripe 退款状态仍显示处理中，有时退款已提交但银行尚未更新，也有时交易较早退款后，原始扣款直接从账单中消失，没有单独的退款行。把这些情况都说成“Stripe 已退款”或“退款失败”，容易让商户和客户沟通混乱。

排查时要同时区分两个问题：商户是否已经成功发起退款，以及客户的银行是否已经把退款显示在账户中。Stripe 的退款状态和银行账单不是同一套系统，客户侧入账时间会受银行和支付网络处理影响。本文适用于商户整理退款状态和客户沟通，不构成对任何个案退款时限的保证；最终请以 Dashboard 状态及 Stripe 对该笔交易的说明为准。

## 先在 Dashboard 确认当前状态

从 Stripe Dashboard 打开原始付款或交易详情，找到关联退款，核对退款金额、币种、创建时间、原始交易和当前状态。部分付款可能发生多次部分退款，因此要确认客户在询问的是哪一笔，而不是只查看原交易总金额。若集成了自有订单系统，也要确认订单系统的退款标签与 Stripe 交易状态同步。

Stripe 支持页面说明，可以在 Dashboard 的 Payments 页面或具体交易页面查看退款状态；对显示为 Refund Pending 的记录，将鼠标移到状态上查看待处理原因。待处理可能与客户银行或金融合作方仍在处理有关，也可能是 Stripe 账户可用余额不足。先读清 Dashboard 的提示，再决定是否需要商户补充资金、等待处理或向 Stripe 支持核实。

不要仅凭客服已经点击退款按钮，就告诉客户“款项已到账”。更准确的说法是说明商户已在某个日期提交退款，并告知客户银行入账需要时间。如果页面显示仍待处理，则应说明退款还在处理，不要将“退款申请已创建”描述成“银行已经退钱”。

## pending：退款尚未完成处理

Refund Pending 表示退款还没有走完平台处理流程。可能是 Stripe 或相关金融合作方仍在处理退款，也可能是账户余额不足。不同原因需要不同的跟进方式，因此查看状态旁边的具体说明很重要。若余额不足，商户应检查 Stripe 余额、待到账资金和 Dashboard 给出的下一步；不要在没有确认原退款状态的情况下，再对同一交易发起另一笔退款。

某些待处理退款会在一段时间后自动失败。Stripe 帮助中心说明，pending 退款在其特定规则下可能于 45 天后失败。不要把这个期限理解成所有退款的固定处理时限，而应将其当作需要持续关注状态的提醒。若已经接近页面说明的处理期限，或退款长时间没有变化，保存退款 ID 和交易信息，再通过 Stripe Dashboard 的官方支持入口咨询。

一旦退款变为失败，应回到原交易确认资金是否退回 Stripe 余额、是否有失败原因，以及是否还允许重新退款。不要仅凭客户表示“没收到”就重新发送资金，因为原交易退款可能还在银行侧处理。应先确认 Stripe 记录，以避免双重退款。

## 退款已提交，为什么客户账户里还没有入账？

银行卡退款通常需要银行或发卡机构进一步处理。Stripe 帮助资料给出的常见时间范围是 5 到 10 个工作日，但这并不意味着每个银行、每个国家或每一种付款方式都完全相同。周末、银行假日和跨境处理链条可能影响客户实际看到记录的时间。商户应说明参考范围并请客户查看交易详情，不要保证某一天一定入账。

如果退款在原始扣款发生后不久发起，银行可能以 reversal（冲正）方式处理：原来的扣款从账单上消失，客户不会看到一条独立的“退款入账”。部分退款也可能表现为原扣款金额降低，而不是单列一笔退款。这时客户看到的结果可能是原始账单金额变化，而非多了一条退款记录。

建议让客户查看原始付款的完整交易详情和待处理交易，而不只搜索“refund”字样。对于被替换、过期或注销的银行卡，客户应向发卡行确认退款是否会转到新卡或关联账户；商户不要自行推测退款去向。若原始交易仍显示完整扣款且已经超过 Stripe 所述常见处理窗口，客户可以联系自己的银行进一步查询。

## 如何提供银行查询所需资料？

在 Stripe 退款详情中，查看该笔卡退款是否有可供追踪的 ARN 或 STAN。Stripe 支持说明，商户可将这些参考编号提供给客户，由客户交给发卡行追踪退款。不是每种付款方式和每个退款都会显示相同编号；如果页面未提供，不要从其他交易复制编号，也不要凭空生成。

给客户资料前核对编号确实对应正确的退款、原始付款和金额。可以提供退款日期、金额、币种、银行卡末四位（如适用）及交易参考号，但不要通过普通电子邮件发送完整卡号、安全码、银行登录信息或验证码。若客户需要补充更多银行资料，让客户直接通过自己的银行官方渠道提供。

沟通中可以简洁说明：“我们已于某日通过原付款方式发起退款，Stripe 当前显示的状态是某状态；如银行暂未显示，可以用该参考号向发卡行查询。”如果是冲正情况，可以解释客户可能看不到单独的退款行，需要比较原始交易。这样比只发送一张没有解释的 Dashboard 截图更清楚，也更保护客户隐私。

## 退款因余额不足而待处理时，商户该做什么？

确认 Stripe 提示属于账户资金不足后，检查 Stripe 余额及收款、付款和退款记录，确认退款金额是否已经扣除或仍在待处理。如果需要补充资金或等待未来款项可用，按 Dashboard 提示和账户当前可用选项处理。不要在后台自有订单系统中提前把退款标记为完成，除非 Stripe 状态和公司流程允许这样做。

商户应把“客户已申请退款”“退款已创建”“退款处理中”“退款成功或失败”作为不同业务阶段记录。对客户承诺退款的时点、实际发起退款的时点和客户银行最终入账的时点也各不相同。订单页面可向客户展示准确的阶段，客服工具中记录跟进日期，避免客户每次联系都要重新解释一次。

如果余额问题持续存在，或账户状态限制了退款能力，通过 Stripe Dashboard 内官方支持联系 Stripe。准备账户ID、退款ID、原始付款ID、金额币种、退款创建时间和状态提示即可。不要将业务登录口令或完整支付信息发送给所谓的代理客服。

## 商户和客户的核对清单

商户可以按以下顺序处理：

1. 打开 Stripe Dashboard 中的原始付款，确认对应退款记录及金额。
2. 读取退款当前状态和 pending 说明，确认平台仍在处理还是需要余额等操作。
3. 核对退款是否部分退款、是否有多笔退款，以及退款是否对应正确客户和订单。
4. 若退款已提交，告诉客户平台提交日期、参考的工作日范围和银行查询方式。
5. 如有 ARN 或 STAN，只分享与该笔退款匹配的参考号，并提醒客户联系发卡行。
6. 超过常见处理范围且银行仍查不到时，先由客户向银行核实，再由商户通过 Stripe 支持查询平台侧状态。
7. 退款失败时先查看原因和原款资金状态，确认后再决定是否重试。

客户可以核对原始扣款、待处理交易和退款记录的账单状态，必要时联系发卡行。客户若在账户里看到的是原始扣款消失而没有退款行，可能是冲正或部分冲正的显示方式。若商户和银行提供的信息矛盾，应通过交易编号和退款参考号继续追踪，不要重复提交同一笔退款请求。

## 常见误区

**“退款状态成功”就一定立刻到账。**  
平台状态与银行账户显示时间不同，客户可能还需要等待银行处理。

**只找一条新的退款流水。**  
若银行采用冲正处理，原扣款可能消失或金额变化，未必会新增单独的入账行。

**pending 就再点一次退款。**  
先读 pending 原因并确认资金状态，重复退款可能产生多次退款请求。

**把 5 到 10 个工作日当成绝对承诺。**  
这是 Stripe 给出的常见银行卡处理参考范围，具体速度受银行、国家和付款方式影响。

## 总结

Stripe 退款处理中或客户未收到时，先在 Dashboard 确认退款状态和待处理原因，再区分 Stripe 仍在处理、退款已提交但银行未显示、冲正或退款失败。向客户准确说明退款提交日期；如页面提供 ARN 或 STAN，可让客户向发卡行查询。不要在状态不清时重复退款，也不要把银行卡完整信息发送给任何人。
