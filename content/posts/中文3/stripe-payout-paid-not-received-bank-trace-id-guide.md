# Stripe已显示付款已到账但银行没收到？核对打款状态、账户和追踪编号

商家在 Stripe Dashboard 看到款项已经支付，银行账户却没有入账，或者预计打款日期不断延后，通常需要先区分“可用余额”“Stripe 已发起打款”和“银行已记账”三个环节。Stripe 的付款日程决定平台多久发起一次打款，但不决定一笔交易何时从待处理余额变为可用余额；银行节假日、账户验证、错误的收款账户或首次打款等待期，也可能造成页面日期与实际到账不同。

本文依据 Stripe 官方支持页面整理，适用于直接使用 Stripe 的商家，以及部分 Stripe Connect 账户。通过第三方平台收款的卖家，可能需要先联系该平台；Custom Connected Account 通常也要由平台联系 Stripe。首次打款周期、银行处理时长和可用功能会按国家、业务类型及账户状态不同，以下不构成固定到账承诺。

## 先看 Dashboard 中这笔款处于哪个状态

登录 Stripe Dashboard，打开 Balances（余额）或 Payouts（打款）页面，找到具体交易。查看金额、币种、预计打款日期、状态和 Account details（账户详情）里的收款账户。确认页面显示的是 Pending balance（待处理余额）、Available balance（可用余额）、In transit（转账中）还是 Paid（已支付）。这些状态代表不同阶段，只有对照具体一笔打款，才能知道要找 Stripe、平台还是银行。

待处理余额通常尚未到可打款阶段；已安排或预计日期是计划信息，不等于资金已离开 Stripe；已支付或转账中则表示打款已由 Stripe 发出，银行还可能需要处理时间。Stripe 官方指出，定期打款频率不会缩短交易资金变为可用余额所需的结算时间。比如账户设置为每日打款，也只会发送已经达到可用条件的资金，不会把尚在处理的交易提前打出。

同时核对预期收款账户。商家可能在 Stripe 内保存了多个外部账户，或通过平台接入后使用了与自己想象不同的收款账户。Stripe 支持页面建议在具体 payout 的账户详情中确认目的银行。不要因为最近更换了收款账户，就默认已经发起的打款会转到新账号。

## 首次打款与账户验证

首次 Stripe 打款可能比后续周期更久。Stripe 官方说明，首次付款通常会安排在成功收取第一笔款项后的7至14天内，但会因国家、行业风险和账户情况而更长。后续打款按账户所适用的计划执行。核对首次打款时，应从第一次成功收款日期开始查看，而不是只从订单创建日或客户下单日期推算。

若预计打款日期不断推迟或被改到未来，Stripe 官方指出，常见原因是账户验证尚未完成。账户所有者应检查 Dashboard 和注册邮箱中是否有补充资料要求，例如身份、企业或受益所有人信息。通过第三方平台创建的 Stripe 账户，可能需要在平台提供的连接账户页面完成验证。不要忽略账户页面的未完成任务，也不要通过邮件里不熟悉的链接上传敏感资料；从已知的 Dashboard 登录入口核对待办事项。

账户验证是收款审核，不等于客户支付失败。客户订单可能已成功支付，但向商家的银行打款暂时无法发起。先确认订单支付状态与 payout 状态分别如何，再完成官方页面要求的验证。不要试图通过频繁更改企业信息、切换银行账户或重复提交相同文件来规避审核；如资料被拒，查看具体原因并按照提示补充清晰有效的文件。

## 已发出但银行还没有记账

Stripe 的官方支持说明，如果打款发出还不到5个工作日，资金可能正在由银行处理；周末和银行假日会造成延迟。工作日计算应依据账户所在国家的银行营业日。银行收到付款后，可能还需要额外时间更新账户记录。先在 Dashboard 确认这笔交易确实已经发出，再按银行入账流程等待；不要因为普通转账还没有当天显示，就再次发起一笔相同金额的手动转账。

如果已超过预计日期5个工作日，联系收款银行查询。准备银行账户信息、预计日期、准确金额、付款方名称 Stripe，以及 Dashboard 中该笔 payout 的 Trace ID（打款追踪编号）。Stripe 官方说明，这一编号由其合作银行为打款生成，银行可以用作参考号追踪资金。在 Dashboard 的 Payouts 页面打开具体打款，查看 Overview（概览）部分的 Payout Trace ID，再通过银行官网或卡片背面的正式电话查询。

若银行查不到该款项，请向银行请求书面确认，说明他们尚未收到 Stripe 付款。某些 Stripe Connect 账户需要由平台持有人向 Stripe 支持提交这类证明；Stripe 由于服务协议限制，可能无法直接向连接账户提供全部打款信息。不要将银行口头答复与正式追踪结果混为一谈，按你账户类型使用对应支持路径。

## 银行账户改过、旧账户已关闭或资料填错

如果在打款已经发起后才更新银行资料，这笔转账通常会继续前往发起时保存的旧账户；新资料只会影响之后的打款。更换银行账号不能追溯重定向已经在途的款项。先查看具体打款的目的账户和发起时间，再联系原银行。向银行提供账户末几位、预期日期、金额和付款方，询问该账户是否仍能接收转账。

若旧银行账户已经关闭，Stripe 的帮助页面说明，银行可能会把资金退回 Stripe，也可能联系账户持有人处理；退回过程可能需要最多5个工作日。等待原银行确认资金是否退回之前，不要不断更改账户信息或提交重复的付款请求。若银行确认款项已退回，检查 Stripe 是否在余额中显示该笔资金重新可用，以及是否需要更新并验证新的账户。

如果 Stripe 账户中的路由号或账号输错，但对应的真实银行账户存在，款项可能已送到错误账户；如果账户不存在，银行可能会将其退回。请尽快核对 Dashboard 中登记的账号，并联系相应银行和 Stripe 官方支持。不要在公共页面、邮件转发或客服聊天中发送完整的银行账号；使用官方安全渠道提交所需资料。

## Dashboard 显示 Paid 但余额不符

先核对金额和币种。Stripe 可以按不同结算货币创建打款，银行账户货币与打款币种不同时，银行端显示的折算数额可能不同。还要查看是否有多笔 payout 合并、某一笔退款或手续费影响可提现余额，以及 Stripe Dashboard 是否展示的是净额。银行账单中的交易日期也可能与 Stripe 的预计日期相差，因为两边的时区和记账日定义未必一致。

在多币种账户中，某些币种可能需要达到最低打款金额才能发出。若余额低于该币种门槛，Dashboard 可能暂时无法启动 payout；适用的金额和解决方式依货币、国家与账户功能不同。不要按别人的截图推断自己账户的门槛，查看 Stripe 官方 Dashboard 提示及货币说明。

如果商家通过第三方电商或平台使用 Stripe，Dashboard 中的 Stripe 款项、平台的销售收入和银行到账记录可能是三个不同账本。对照订单编号、支付意图、平台结算记录和 Stripe payout，确定资金在哪一阶段停住。平台也可能安排资金拆分或延后转账；遇到这种情况，先找平台支持确认其连接账户设置。

## 建议的排查顺序

1. 打开 Stripe Dashboard 的 Balances 或 Payouts，定位具体款项并记下状态、日期和金额。
2. 区分待处理余额、可用余额、已发起转账和银行已记账。
3. 检查 Dashboard 与邮件中是否有账户验证或补充资料要求。
4. 核对该笔打款的收款银行账户，确认是否为旧账户或填错账户。
5. 若已发出未满5个工作日，考虑银行营业日与节假日并继续观察。
6. 超过5个工作日后，携带金额、预计日期、付款方和 Payout Trace ID 联系银行。
7. 银行确认未收到后，按 Stripe 账户类型向 Stripe 或平台提交银行书面证明。
8. 若用的是 Payoneer 或第三方平台，先确认 Stripe 已发给中间收款账户，再追查下一段转账。

## 联系前准备的信息

整理 Stripe 账户或平台名称、payout ID、金额和币种、预计日期、Dashboard 状态、收款账户末几位、Trace ID、银行是否查询及书面答复、账户验证通知，以及最近是否更改银行资料。通过 Stripe Dashboard、平台账户和银行官方应用联系支持。不要提供密码、一次性验证码、完整银行卡安全码或远程控制权限。
