# Stripe Sigma 数据分析入门：SQL 报表、支付对账与订阅指标

支付和订阅业务的数据分散在付款、退款、客户、发票、余额交易和订阅等不同对象中。只在 Dashboard 逐个搜索交易，适合排查单笔问题，却很难稳定回答“本月退款率是否变化”“哪些付款方式的失败增多”“订阅续费收入和实际到账有什么差异”等运营问题。Stripe Sigma 提供 Dashboard 内的 SQL 查询环境，团队可以从 Stripe 数据中构建自定义报告，并保存查询重复使用。[Stripe Sigma 产品介绍](https://stripe.com/sigma)；[Dashboard 搜索与 Sigma 说明](https://docs.stripe.com/dashboard/search)。

Sigma 适合探索与分析 Stripe 账户数据，但不能自动替代财务总账、订单数据库或应用事件日志。查询结果是否准确，取决于业务定义、表之间的关联方式、时间窗口、退款和争议的处理口径，以及 Stripe 账户是否涵盖所有销售渠道。建立报表前先明确指标要回答的问题，再选择数据对象和验证方式。

## 先确定指标口径和数据对象

“收入”不是一个单一数字。客户付款金额、扣除退款后的净额、Stripe 余额变化、银行实际到账以及会计确认的收入，各自可能对应不同的数据对象与时间点。Stripe 交易数据可包含付款、退款、订阅、发票、payouts 等资源。若要分析 Stripe 扣除费用后余额变化，可以从 Balance Transactions 方向思考；若要分析订阅账单，则应结合 Subscription、Invoice 及发票行项目；若关注客户是否实际完成付款，则需要按付款对象状态筛选。

为每张报表写下指标定义，例如：月份按 UTC 还是业务时区划分；退款按照退款创建日还是原始付款所属日统计；支付失败次数是否包含重试；试用中的订阅是否计入活跃订阅；争议中资金是否先从净收入中扣除。把这些定义放在报表名称或说明里，避免不同团队拿着标题同为“月收入”的图表却使用不同算法。

不要把数据库中的金额整数直接当作主币种单位。Stripe 金额通常需要结合币种和相应的最小单位解释；多币种账户还要确定是否换算成报告币种、使用哪个时间点的汇率，以及汇率变动如何处理。跨币种汇总但不做转换时，数值相加没有清晰业务含义。

## 用 SQL 从问题开始，而不是堆大查询

首次使用 Sigma 时，可以从 Dashboard 的示例查询或预置模板开始。Stripe 产品介绍列举了付款、payouts、客户、订阅和退款等可组合的数据，并提供查询编辑和保存功能。先选一个可验证的小问题，再扩展查询，通常比一次编写多表巨型 SQL 更容易发现关联错误。

例如分析支付失败趋势，可以先按时间窗口汇总付款状态，再拆分付款方式和失败原因；分析退款，可以将退款对象与原始付款关联，并确认同一付款存在多次部分退款时不会被重复计算；分析订阅收入，则要区分订阅状态、发票状态和成功支付。SQL 结果应抽取少量已知交易，与 Dashboard 里的对象详情逐条核对，确认金额、状态、时间和币种一致之后再用于决策。

常见数据分析错误包括：将一对多关联造成的重复行当成真实交易；把测试模式和正式模式数据混在一起；漏掉部分退款或失败的付款尝试；把已创建发票误当成已收款；以及把授权金额、capture 金额和余额净额混为一谈。查询越复杂，越需要通过对象 ID 和已知交易样本逐层验证，而非只观察结果看起来是否合理。

## 订阅报表要区分发票与访问权限

订阅报表常见需求包括活跃订阅数、续费金额、试用转化、取消趋势和未收款发票。Subscription 对象描述订阅关系和周期，Invoice 描述某次账单及其项目，付款对象描述收款流程，应用自己的授权记录则决定客户实际能使用什么服务。这些对象有时会在不同时间变化。

例如客户可能仍有 active Subscription，但最近一张 Invoice 付款失败，应用需要按 dunning 策略决定权益是否宽限；也可能客户已取消订阅但当前计费周期仍有效。仅统计 `status=active` 的订阅，不能直接等同于已收款客户数或本月确认收入。报表应为续费付款、试用、宽限期、取消和退款制定清楚口径，并和服务端权限状态分开。

在分析留存和流失时，需定义按客户还是按订阅计数；一个 Customer 可能拥有多个 Subscription。升级降级也会产生订阅更新或 prorations，若只比较周期末金额，可能忽略周期中的变更。将查询中的过滤条件、日期边界和对象关联写在报表说明中，便于后续复核。

## 余额交易和财务对账

Balance Transaction 可用于观察 Stripe 余额的变动、费用和净额等信息。它与“客户付款成功”并不是同义词：退款、争议、费用、调整和 payout 都会影响余额。财务对账可按交易 ID、source ID、币种、类型与可用时间关联内部订单和银行流水，查找金额差异或待结算项目。

做 payout 对账时，区分余额交易的创建时间、可用时间和银行到账日期。节假日、结算计划、币种和账户设置都会影响到账时间。Sigma 报表可以筛查尚未匹配的交易，但最终的现金余额和财务结账仍应与银行流水、总账和 Stripe Dashboard 核对。不要将 Sigma 某个 SQL 汇总数直接视为审计结论。

建立金额差异排查表时，保存 Stripe object ID 和内部订单 ID 的映射；记录汇率、费用、退款、争议和人工调整。若查询使用的是 payout 所含 balance transactions，也要确认多笔交易合计与 payout 金额之间的差额解释正确。

## 保存查询与定时结果

团队可以保存常用查询，用于复用和协作；Stripe Event 类型文档也列出 `sigma.scheduled_query_run.created` 事件，其语义是 Sigma 定时查询运行完成。若账户启用定时查询能力，可围绕月度对账、退款异常或续费失败报表设计稳定的运行节奏，并配置相应的通知或后续数据处理。[Stripe Event Types](https://docs.stripe.com/api/events/types)。

定时结果应作为分析输入而非无人审核的财务指令。每次运行要监控成功或失败、结果行数、更新时间和查询版本。若字段或表结构变化、数据处理延迟或 SQL 条件意外筛掉数据，自动导出的空报表可能被误认为业务突然归零。为关键报告保留负责人，并为异常数量设置简单的质量检查。

若通过 Queries API 等方式将结果接入内部系统，先确认当前 API 与账户权限支持情况，并对 API 凭据进行安全管理。不要把 Sigma 查询密钥或 Stripe Secret Key 放在公开前端、代码仓库或共享文档里。数据导出还应遵循最小必要原则，设定访问范围、存储位置和保留期限。

## 隐私、访问控制与可重复性

Sigma 报表可能包含邮箱、客户标识、交易和账户信息。只授权需要分析工作的人员访问；导出到表格、数据仓库或第三方 BI 工具时，检查接收方权限、传输方式和数据保留策略。常规分析尽量使用聚合数据或内部不可逆标识，不要为了方便将完整个人资料复制到所有团队空间。

将 SQL 查询视为可维护的业务资产：记录名称、目的、负责人、币种/时区口径、运行频率、依赖表和最近验证日期。更新查询时留存变化原因，避免某个过滤条件被改掉后没人知道收入图表为什么突然跳变。关键报表的结果可以与 Dashboard 导出或已知交易样本定期抽查。

## 常见问题排查

**Sigma 查询结果比 Dashboard 付款列表多：**检查是否包含失败或未 capture 的交易、是否 join 出重复行、是否包含了不需要的 Connect 账户范围，以及测试与正式数据是否混合。

**Invoice 金额与余额到账金额不同：**检查付款是否成功、是否有退款或争议、手续费和币种换算如何处理，并区分发票金额与 Balance Transaction 净额。

**报表每月金额不同步：**检查时区、日期边界、付款创建时间与可用时间、月末异步事件，以及周期订阅和 prorations 的定义。

**定时查询完成但下游没收到结果：**检查 `sigma.scheduled_query_run.created` Webhook 是否订阅、签名验证、队列和异步处理状态。事件表示查询运行结束，仍要读取结果状态并确认输出完整。

**结果突然变成空表：**验证筛选条件、状态枚举和时间参数，随机抽取最近对象对比，再检查查询数据范围和账户上下文。不要未经确认就将空值当成业务结果发送给管理层。

## 上线检查清单

- 每个指标有明确的时间、币种、退款和状态口径。
- 查询数据范围、对象关联和 Connect 账户范围已核对。
- 使用已知订单 ID 与 Dashboard 对象逐笔验证 SQL 结果。
- 订阅、Invoice、付款、退款、余额和应用权限没有被混为一谈。
- 定时查询有运行状态监控、负责人及异常结果检查。
- 对 SQL、API 凭据、导出文件和个人数据设置访问与保留规则。
- 财务数字与 Stripe Dashboard、银行流水及内部账本定期对账。

## 总结

Stripe Sigma 可在 Dashboard 中用 SQL 探索 Stripe 业务数据并建立可复用报告，帮助团队从逐笔查找转向支付、订阅、退款和余额趋势分析。准确的指标口径、多表关联验证、币种与时间处理和隐私控制，是报表可靠的关键。把 Sigma 作为运营分析与对账工具，并与应用数据库、财务账本和银行流水互相验证，才能让查询结果真正支持业务判断。

Sigma 的可用功能、权限和数据表会受账户配置与 Stripe 产品变更影响。具体使用前请在当前 Stripe Dashboard 和官方文档中确认账户可用能力。
