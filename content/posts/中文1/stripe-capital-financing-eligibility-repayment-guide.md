# Stripe Capital 资金方案指南：资格、固定费用与销售额还款

Stripe Capital 面向符合条件的企业提供资金方案，可能包括商业贷款或商户现金预支。与需要商家自行编写支付 API 的功能不同，Capital 主要通过 Stripe Dashboard 展示资格和报价，企业查看可选金额、费用与还款方式后申请。可用方案、提供方、资格和具体条款会因地区与账户而异，因此文章中的通用流程不能替代 Dashboard 中针对企业的正式报价和合同。

理解资金成本和还款节奏，比只看“可以拿到多少钱”更重要。Stripe 的产品介绍说明，部分方案采用固定融资费用，并按每日销售额的一定比例自动扣还；某些贷款还可能有每个还款周期的最低应付金额。企业应在接受之前逐项阅读本账户报价与法律文件，评估收入波动、退款、平台余额和银行账户扣款安排。

## 一、如何查看账户是否有资格

Stripe 会依据账户和支付历史等因素评估是否向企业展示报价。商家可以登录 Stripe Dashboard 查看当前是否有资格和可用选项。资格可能随业务表现和时间变化，今天没有报价不代表以后永远没有；同样，Dashboard 中出现报价也不等于最终申请已经批准。融资申请可能需要进一步审查。

查看时确认使用的是正确的 Stripe 账户、公司主体和业务地区。若公司拥有多个账户或 Connect 平台结构，应查清报价适用的法律实体、收款账户和还款主体。不要将一家关联公司的销售额或另一个账户的付款表现直接当成当前报价的资格依据。

## 二、贷款与商户现金预支并非同一种安排

Stripe Capital 的方案可能包括贷款和商户现金预支。它们的合同性质、提供方、披露内容和还款条款可能不同。不要仅根据界面上显示的资金金额判断两种方案在法律或会计上完全相同。阅读正式报价，确认融资类型、费用总额、付款比例、最低付款、期限或其他约定。

Stripe 对产品的公开介绍说明，融资费用可能是固定费用，并展示按销售额比例自动还款的机制。固定费用并不意味着每种产品、地区或报价的实际合同条款都相同，也不代表资金没有成本。对比报价时，应看企业最终收到的金额、必须偿还的总金额、销售扣款比例、最低应付规则和额外银行扣款安排，而不是只关注展示的比例或所谓“快速到账”。

如有不清楚的合同术语、贷款提供方、抵扣规则或违约条款，应联系 Stripe 支持或专业财务与法律顾问确认，不要依赖营销页面的简化说明。

## 三、按销售额还款如何影响现金流

销售额还款通常会根据符合条款定义的销售活动，按固定比例扣除一部分资金用于还款。销售增长较快时，偿还速度可能更快；销售较低时，扣款金额可能相应减少。企业仍需核实具体计算基数：哪些交易纳入销售额、退款和拒付如何调整、扣款在何时入账，以及余额不足时如何处理。

不同企业的现金流并不只取决于 Stripe 处理的支付额。退款、税费、供应商结算、广告预算、工资、订阅续费季节波动都可能影响可用资金。接受报价前，应按高、中、低销售情景测算每个周期可能扣除的金额，并检查扣款后是否仍能支付必要运营成本。不要把销量增长预测当成确定收入，也不要以为“按销售额扣款”就不存在最低付款或银行账户扣款。

公开页面指出，一些 Stripe Capital 贷款在每个付款周期有最低应付金额。如果通过销售扣除的金额未达到合同要求，剩余部分可能在周期结束时从银行账户自动扣取。具体是否适用于当前报价，要以正式条款为准。企业应确认关联银行账户可用、账户信息正确，并预留足够资金覆盖可能的周期末扣款。

## 四、接受报价前的核对清单

将报价保存下来，并与企业的现金流预算和其他资金方案比较。至少确认：

- 资金提供方与融资类型；
- 实际拨付金额和资金入账时间；
- 固定费用或其他应付成本；
- 销售额扣款的计算方式与比例；
- 每个付款周期的最低应付金额；
- 银行账户扣款发生的情形和日期；
- 退款、争议和销售波动如何影响还款；
- 提前偿还、结清或其他条款；
- 合同适用主体、币种和地区；
- 申请审批、信息披露及数据授权要求。

企业还应明确谁有权代表公司申请融资、查看报价和接受合同。对于内部审批，应保留报价版本、接受日期、审批记录和最终协议，避免财务部门只看到银行入账却不清楚对应的还款义务。

## 五、入账、对账与财务记录

资金到账后，财务系统应能区分融资款、销售收入和 Stripe 余额中的其他交易。融资款不是销售收入，也不应通过一般订单流水重复计入营收。依据合同和会计政策记录负债或其他适用科目，并与会计师确认费用确认方式。

还款对账可以按周期核对 Stripe Dashboard 显示的已还金额、余额扣款、银行账户自动扣款、未结余额和预计结清进度。每项记录最好关联融资协议 ID、交易日期、币种、扣款金额和银行流水参考。若销售收入已在支付对账中作为毛额记录，还应避免把Capital扣款误记为新的退款或处理费。

若发现扣款金额与内部预估不同，先检查周期交易、退款和最低付款条款，再联系 Stripe 查询。不要只用每日销售额乘显示比例估算最终账单，因为合同中可能有其他调整因素。

## 六、常见问题与误区

**Dashboard 没有 Capital 报价。** 资格由 Stripe 根据账户情况评估，资格和产品可用性可能变化。确认账户主体和业务地区后，可以过一段时间重新检查，或询问 Stripe 是否提供适用说明；不要尝试用错误的账户信息申请。

**有报价但资金尚未到账。** 查看申请是否已提交、是否仍在审查、是否需要补充信息，以及 Dashboard 展示的拨付时间。公开页面所说的典型到账速度不是对每一笔申请的保证。

**还款扣款高于预期。** 对照合同中的销售计算口径、最低付款、退款调整与周期末银行扣款条款。保存相关 Dashboard 页面和银行流水，向 Stripe 支持核对具体记录。

**销售下降，仍然担心还款。** 检查合同所约定的最低付款、扣款时间和资金来源。不能仅根据“按销售额还款”的概述推断低销售月份没有固定应付义务。

**把融资当作没有成本的预付款。** 固定费用和还款义务仍需纳入融资成本与现金流分析。比较任何外部资金方案时，按照企业实际合同和预计偿还时间核算总成本。

## 七、运营期间的监控

每周或每月将实际销售扣款与预算对照，观察季节变化、退款率和余额波动。若还款由多个渠道完成，确认 Stripe 余额扣款和银行账户扣款不会因对账滞后而被重复记账。财务负责人还应关注资金到账、预计剩余本金或应还余额、费用和下一次最低付款日期。

由于资金方案可能因区域、提供方和法规而不同，定期检查 Stripe Dashboard 和最新协议。业务扩张、法律实体变化、账户迁移或收款方式改变后，确认当前融资协议的还款安排是否继续按原账户执行。遇到合并、关闭账户或变更银行资料等重大操作，应先联系 Stripe 了解对未结余额的影响。

## 总结

Stripe Capital 为符合资格的企业提供可能包含贷款或商户现金预支的资金方案。具体报价、融资类型和提供方会根据账户与地区变化。公开介绍中的固定费用和按销售额还款有助于理解产品大致机制，但企业必须依照 Dashboard 里的正式报价和合同核对金额、比例、最低付款与银行扣款条款。

在接受之前，将还款情景纳入现金流预算，安排合同审批和财务记账；接受之后，持续核对 Stripe 扣款、银行流水和剩余应还义务。不要把融资入账视为销售收入，也不要假设销售额还款方式意味着没有周期最低付款。需要解释合同或税务处理时，联系 Stripe 及专业顾问获取适用于企业自身情况的意见。
