# Stripe Terminal 国家和读卡器适用指南：账户、门店与币种

Stripe Terminal 让商家在实体门店、展会或服务现场接受线下付款，但线上 Stripe 账户能够处理支付，不代表同一账户可以在任意国家连接任意读卡器。部署前至少需要核对四个条件：接收资金的 Stripe 账户国家、Terminal Location 所属国家、当地可用的读卡器型号，以及终端交易可使用的币种。

Terminal 的国家支持和硬件可用性可能随时间变化。官方区域文档按国家列出智能读卡器、移动读卡器和 Tap to Pay 等产品；有些设备可能是公开预览或私人预览。采购前应以 Stripe 当前区域页面和账户 Dashboard 为准，不要仅依据其他国家门店的部署经验买硬件。

## 一、账户国家与读卡器 Location 必须匹配

Stripe 文档说明，处理 Terminal 付款时，收款 Stripe 账户和读卡器关联的 Location 必须位于同一国家，并以当地货币受理。这个限制意味着企业不能简单地把在一个国家注册的 Stripe 账户拿到另一个国家的实体门店收款，然后仅通过 API 创建该国的 Location 来绕开地区条件。

集团跨国运营时，应按每个经营实体和门店所在地规划 Stripe 账户结构。若采用 Connect，确认平台账户或连接账户中，哪一方符合该国家的 Terminal 收款要求。不要等设备采购、店员培训完成后才发现资金接收账户与 Location 国家不匹配。

门店地址需要维护真实且正确。Location 不只是一个展示名称，它还用于识别读卡器所在业务地点和区域配置。一个商家有多个国家的门店时，应为每个地点建立清晰的内部编码和地址，并让读卡器与正确地点对应。更换设备、搬迁门店或临时使用展会地点时，也要更新库存台账和终端关联。

## 二、读卡器型号和连接方式因国家而异

Stripe Terminal 并非所有 Reader 在所有市场同时可用。智能读卡器、移动读卡器以及 Tap to Pay 的覆盖范围不同，具体型号还可能处于预览阶段。企业需要根据官方国家表确认预期设备型号是否支持，确认采购渠道、软件集成方式和运营支持条件后再下单。

智能读卡器通常适合固定柜台或需要独立显示交互步骤的门店；移动读卡器适合流动服务、餐厅桌边或临时活动；Tap to Pay 则依赖符合要求的移动设备和当地支持情况。选择设备时，应结合网络环境、收银软件、店员培训、电池续航、交易量和维护能力，而不是单看设备外观或价格。

若某型号仅在私人预览或公开预览中提供，不要把它视为所有账户都能立即采购的正式功能。检查商家的 Dashboard 是否展示该型号，并确认 Stripe 对账户资格、地区和支持方式的说明。项目计划中应准备可用型号的替代方案，避免预览资格变化导致门店无法按期上线。

## 三、本地货币与交易金额

Terminal 的区域规则通常要求使用 Location 国家对应的本地货币。线上支付支持多币种，并不自动意味着线下读卡器也能使用相同币种受理。跨国门店应为各国销售流程配置正确的币种和价格，结账金额由后端计算并与订单一致。

Stripe API 使用最小货币单位传金额，且某些货币有零位小数或特定规则。商家在开发时应依据 Stripe 的币种文档决定金额表示，不要对所有货币一律将金额乘以 100。线下退款、部分退款、税费与小费也应使用正确币种，确保支付、订单系统和财务账簿可以对齐。

如 Stripe 账户的结算币种与本地收款币种不同，还要区分客户付款呈现币种、交易币种和资金结算币种。汇兑和结算方式会影响财务对账与实际到账金额，应按 Dashboard 设置和 Stripe 费用说明评估。不可仅凭终端的本地价格显示判断企业最终以何种币种收到资金。

## 四、跨国门店实施步骤

一个稳妥的部署流程可以分为以下阶段：

1. 列出门店的国家、法律实体、Stripe 账户和预期销售币种。
2. 在 Stripe 官方 Terminal 区域表逐国核对可用设备和 Tap to Pay。
3. 确认账户与 Location 国家要求，并在测试环境中建立代表性地点。
4. 核对 Reader 接入方式、网络要求、后台收银软件和店员操作流程。
5. 用测试交易覆盖成功、取消、退款、断网和重启后的状态恢复。
6. 通过 Webhook 和服务端订单状态确认付款，不只依赖设备屏幕上的展示。
7. 选择一间门店试运行，检查收据、币种、税务、退款和每日对账。
8. 试点通过后再分批部署到其他地点，并记录读卡器序列号和所在门店。

如果企业迁移门店或更换 Stripe 账户，先确认旧 Location、读卡器和待处理交易如何管理，再执行迁移。不要在没有核对未完成 PaymentIntent、Reader 注册和财务对账的情况下直接删除旧地点。

## 五、常见问题排查

**读卡器无法注册。** 检查设备型号是否适用于账户国家，账户与 Reader Location 是否同国，设备是否已在其他地点注册，以及网络和系统配置是否正确。不要通过重复创建不同国家的 Location 来绕过硬件支持限制。

**PaymentIntent 币种在读卡器侧不受支持。** 检查创建 PaymentIntent 的币种与门店当地规则、账户国家和所用支付方式。跨境线上币种可用，不代表该线下设备也能处理该币种。

**Tap to Pay 在某个国家不可用。** 分别检查 Stripe 商户国家、设备操作系统、设备型号、App 能力和账户资格。不要只看手机硬件支持 NFC 就假定 Stripe Terminal Tap to Pay 已可用。

**跨门店报表无法核对。** 检查 Location ID、Reader ID、内部门店编码、PaymentIntent 和订单之间是否完整关联。统一使用内部地点标识，避免两个门店名称相似造成日报错归属。

**设备或国家支持状态改变。** 重新查看官方区域表与 Dashboard，确认该变化适用于现有账户还是新注册账户，并联系 Stripe 支持了解迁移或替代设备方案。

## 六、上线检查清单

- 收款 Stripe 账户国家与门店 Location 国家一致。
- 每个国家的设备型号在当前 Terminal 区域表中可用。
- 预览阶段设备或功能已获得该账户访问资格。
- Location 地址和内部门店编码准确且可维护。
- 线下交易币种符合地点和账户适用规则。
- 金额在 API 中按币种最小单位正确处理。
- 订单、PaymentIntent、Reader 与 Location 可相互追踪。
- Webhook 重复事件不会重复履约或重复记账。
- 退款、收据、税费和结算币种已在试点门店验证。
- 有设备停机、联网失败、搬迁和账户变更的运营流程。

## 总结

Stripe Terminal 的线下部署取决于账户所在地、读卡器 Location、硬件国家支持和本地交易币种。在线上可处理某个国家的支付，不能推导出当地任意设备也可以连接同一账户。跨国商家应逐国规划收款实体和门店，再核对当前可用读卡器及预览状态。

正式采购前从 Stripe 官方区域页面确认设备表和资格，使用小范围门店试运行验证支付、退款与对账。将 Location、Reader、PaymentIntent 和内部订单关联起来，才能在多门店运营时定位设备问题并保持财务记录准确。
