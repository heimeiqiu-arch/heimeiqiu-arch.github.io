# Stripe 手动授权与捕获怎么做？预授权、部分扣款和到期管理

在线购物、酒店预订或服务验收场景中，商家可能需要先确认客户的付款方式可用，稍后再真正收取资金。这种“先授权、后捕获”的流程，可以让商家在发货、确定最终金额或完成服务后再完成扣款，但它也带来授权有效期、最终金额限制和订单状态同步等要求。

Stripe PaymentIntent 可通过手动捕获流程创建授权。支付授权成功后，PaymentIntent 通常进入 `requires_capture`，商家需要在授权可用期间调用 Capture API 捕获资金；如果最终不需要收费，则取消授权。本文介绍授权与捕获的工作方式、部分捕获和多次捕获限制、Webhook 同步以及上线测试。支持能力和授权有效时间会因支付方式、卡网络、地区和账户而不同，务必以 Stripe 当前文档及对象的 `capture_before` 信息为准。

## 授权和捕获分别意味着什么

**授权（Authorization）** 是发卡行批准一笔金额并暂时保留客户可用额度。它让商家知道这笔付款在当时获得授权，但资金并未等同于已经完成收取。

**捕获（Capture）** 是商家请求收取已授权金额。捕获成功后，PaymentIntent 会更新为成功状态，款项进入 Stripe 的余额处理流程。

如果授权后客户取消订单或商家不提供服务，可以取消 PaymentIntent 释放授权。但银行释放额度的显示时间由金融机构决定，客户的账单页面未必马上更新。

手动捕获适合确有“先授权、后确认最终金额”的业务。例如先确认酒店预订、发货前验证可支付、服务完成后按合同收款。若业务可以在客户付款时确定最终金额，自动捕获通常流程更简单，也减少未捕获授权过期的风险。

## 设置 capture_method=manual 的流程

服务器端创建 PaymentIntent 时，将 `capture_method` 设置为 `manual`。具体创建参数要符合所使用的支付方式和 Stripe 集成；不是所有支付方式都支持手动捕获。随后由客户完成支付确认和必要的认证。

典型状态流程如下：

1. 服务端根据订单金额创建 PaymentIntent；
2. 客户完成付款方式确认；
3. 若授权成功，PaymentIntent 进入可捕获状态；
4. 商家根据实际交付金额决定捕获金额；
5. 服务端调用 Capture API；
6. 成功捕获后确认 PaymentIntent 状态并更新订单；
7. 未使用的授权按支持的方式释放，或等待系统自动释放。

捕获前应检查 PaymentIntent 的当前状态和 `amount_capturable`，不要假设只要对象存在就可以扣款。API 捕获操作只适用于处于可捕获状态的 PaymentIntent。

## 授权有效期与到期管理

授权不是长期冻结额度的机制。Stripe 文档指出，未捕获 PaymentIntent 会在一定时间后取消，默认期限通常为 7 天；具体可用时限会因卡网络和交易情境变化。部分 PaymentIntent 的 Charge 信息中可能提供 `capture_before` 时间，可用于估算授权最迟可捕获时点。

商家需要建立授权到期监控：

- 在支付授权成功时记录可捕获金额和创建时间；
- 若对象提供 `capture_before`，保存并设定提前告警；
- 对没有该字段的支付方式按当前官方文档和账户行为制定保守时限；
- 在到期前完成捕获、取消授权或联系客户；
- 不要等到授权最后时刻才发起捕获；
- 如果订单无法在有效期内确认，决定是否需要重新授权，并向客户清楚说明可能再次验证资金。

授权过期后无法保证原授权仍可捕获。重新创建付款流程可能导致新的授权或客户再次操作，因此要先核对原 PaymentIntent 的最新状态和银行显示，避免客户误以为重复扣款。

## 捕获全额、部分金额和多次捕获

Capture API 的 `amount_to_capture` 用于指定本次捕获金额，不能超过可捕获金额。若不传金额，通常捕获剩余可捕获的全部金额。实际捕获规则、货币最小单位和是否可多次捕获，取决于支付方式、网络和账户能力。

许多普通手动捕获流程只支持一次最终捕获：如果实际订单金额低于授权金额，捕获较低金额后，剩余部分会按支付流程释放。不要默认可以先捕获一部分，之后继续捕获剩余金额。Stripe 的多次捕获需要适用的功能支持；仅在符合条件的场景，才通过 `final_capture=false` 保留剩余未捕获金额用于后续捕获。

商家应区分：

- **少于授权金额的最终捕获：** 收取实际应收金额，并释放剩余额度；
- **一次捕获全部授权：** 收取授权金额；
- **多次捕获：** 只有在 Stripe 为该账户和支付方式提供支持时使用，并正确设置最终捕获行为；
- **超出授权金额：** 不能随意捕获超过授权的金额，需根据业务和支付规则重新获取客户授权。

不确定的费用（例如酒店额外消费）可能需要额外授权或支持网络特定的 overcapture 能力。不要把一般的 `amount_to_capture` 当作允许超额扣款的功能。

## 履约和订单状态不要提前确认

授权成功并不等同于资金捕获成功。库存预留、发货、下载权限、服务开通和收入确认要根据业务风险区分：

- 对高风险或需要先验货的业务，可在授权成功后短暂预留库存；
- 对必须先付款再提供的数字服务，通常要等捕获成功再开放完整权限；
- 捕获 API 请求成功后，还要记录返回对象状态；
- 若 API 超时，先查询 PaymentIntent 状态，不要立即再发起另一笔 PaymentIntent；
- 若捕获失败，保留订单为待处理或错误状态并触发人工检查；
- Webhook 重复或延迟到达时，幂等处理履约任务。

通过 `payment_intent.amount_capturable_updated` 等相关事件监控授权金额可捕获状态，并在成功捕获或取消时同步业务订单。监听事件后仍应检验对象的最新状态，避免旧事件覆盖更近的业务状态。

## API 捕获的安全实现

Capture 操作应只由后端执行。前端传入“客户想支付多少钱”不能直接作为扣款金额。服务端需要从已验证的订单、已授权金额、实际交付明细和商家规则计算本次捕获金额。

推荐的后端校验：

1. 当前用户有权操作该订单；
2. PaymentIntent 属于当前内部订单、Customer 和 Stripe 账户；
3. PaymentIntent 处于 `requires_capture` 等可捕获状态；
4. 本次金额不超过 `amount_capturable`，并符合币种最小单位；
5. 当前请求尚未成功捕获，或属于受支持的多捕获流程；
6. 订单没有被取消或已全额退款；
7. 记录操作人、捕获金额、原因和幂等请求 ID；
8. 发生超时后先检索对象状态再决定是否重试。

所有操作都应保留审计记录。若使用 Connect，请确认捕获操作执行在创建 PaymentIntent 的账户上下文中，并核对应用费、转账和捕获金额之间的关系。

## 失败和异常场景

### PaymentIntent 不在可捕获状态

检查客户是否完成支付确认、PaymentIntent 是否需要额外操作、是否已捕获或已取消。状态不符合时，不应盲目重复调用 Capture API。

### 授权已过期

查询 PaymentIntent、Charge 和当前可捕获金额。若已取消或过期，需按商家流程创建新的付款请求，并清楚提示客户可能需要重新授权。不要重复显示旧授权为“已付款”。

### 实际金额比授权少

明确这是一次最终部分捕获还是需要多次捕获。如果是最终收取较低金额，按当前规则捕获并确认未用金额的释放行为。会计系统中同时保存授权金额和实际捕获金额，便于解释差额。

### 捕获请求超时

网络超时不等于捕获失败。先通过 Stripe API 查询 PaymentIntent 最新状态、`amount_received` 和 `amount_capturable`。确认之前请求结果后再执行下一步，避免重复扣款。

### 客户银行仍显示保留额度

如果商家只做了授权，客户可能仍看到临时保留金额；取消或释放后，银行可能需要时间更新。客服可以解释商家侧授权状态，并避免承诺银行端具体更新时间。

## 适用性与客户告知

在客户确认付款前，要清楚解释商家会先授权还是立即收款、最终金额是否可能低于授权额，以及什么时候捕获或释放资金。若最终金额取决于实际使用量、服务完成情况或额外商品，应说明估算金额和调整规则。

手动授权也可能对转换率产生影响：客户看到银行额度被暂时保留，但服务尚未完成或并未立即收费，可能产生疑虑。对不需要预授权的普通销售，不要仅为了“先看卡是否有效”就长期占用客户额度。

## 测试场景清单

- 授权成功后 PaymentIntent 进入预期可捕获状态；
- 正常捕获全额并收到成功事件；
- 捕获低于授权金额，确认余额释放和账单状态；
- 捕获金额超过授权时系统拒绝并显示正确错误；
- 超时后查询现有对象，不创建重复收费；
- 未捕获订单在授权到期前触发告警；
- 取消 PaymentIntent 后本地订单与 Stripe 状态一致；
- 需要客户认证或授权失败时不进入捕获队列；
- Webhook 重复到达不会重复发货或记账；
- Connect 账户上下文、平台费和转账金额符合订单规则；
- 使用测试模式验证状态逻辑，并在真实模式谨慎检查实际银行体验。

## 总结

Stripe 手动捕获将付款拆成授权和收款两个阶段。授权成功时资金尚未完成收取，商家要在有效期内根据实际订单决定全额或部分捕获，或者取消授权。授权时间通常有限，且不同支付方式和网络的规则不同，应监控对象状态及可用的捕获截止信息。

把捕获操作限制在后端，基于服务端订单计算金额，使用幂等和 Webhook 更新支付状态，并在请求超时时先查询对象，可以减少重复扣款和错误履约。上线时还要向客户解释授权和最终收费的区别，并根据自己的服务流程决定何时预留库存、开放权益和确认收入。
