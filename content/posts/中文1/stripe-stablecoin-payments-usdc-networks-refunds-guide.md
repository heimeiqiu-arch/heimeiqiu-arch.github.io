Stripe 稳定币支付让商家可以通过 Checkout 等产品接受部分稳定币付款。客户选择加密钱包和支持的支付网络，在 Stripe 的支付流程中连接钱包并确认交易；完成后，Stripe 会按商家当地货币把款项结算到 Stripe 余额。这样客户可以使用受支持的稳定币付款，而商家仍通过 Stripe 余额和现有结算流程对账。

稳定币付款仍然有明确的资格、网络、币种和退款规则。客户地点与商家可开通国家不同；同一代币在不同区块链网络也不等同；退款会以稳定币退回原钱包，且当前没有传统卡片式争议流程。本文根据 Stripe 当前文档介绍接入前需要核对的事项，正式启用前应以 Dashboard 实际显示为准。

## 当前支持的稳定币与网络

Stripe 当前文档列出稳定币付款可接受的代币和网络，包括 USDC 在 Ethereum、Solana、Polygon、Base 和 Tempo 网络上；USDP 在 Ethereum 与 Solana 网络上仅对美国客户支持；USDG 在 Ethereum 网络上也仅在美国支持。不同代币和网络的可用性不能互相推断，商家应按自己的账户、客户和交易上下文确认实际展示选项。

客户在 Stripe 支付流程中选择可用币种、网络和钱包。商家网站不应要求客户自行把代币转到任意地址，也不应在订单页面展示未被 Stripe 支持的网络地址。交易应通过 Stripe 提供的 Checkout 或 Elements 流程完成，并由 Stripe 对象和 webhook 返回结果。

稳定币付款目前以 USD 作为展示币种，其他展示币种在 private preview 中。商家可收到本地货币结算到 Stripe 余额；这与客户钱包中的稳定币网络、资产和商家银行账户的结算货币是不同层次。财务团队应从 Stripe 余额和交易明细中核对最终入账，而不是仅根据客户支付的代币数量估算本币收入。

## 商家地区与客户地区

Stripe 文档说明，客户可以在全球范围内使用稳定币支付，但商家只有在支持的国家或地区才能开通。当前文档列出美国，以及欧盟、香港、墨西哥和瑞士等区域的 private preview 资格。private preview 需要符合条件并由 Stripe 开放，不能假设所有当地商家都能直接在生产环境看到该方式。

受制裁地区等限制也适用。商家应在 Dashboard 查看稳定币支付方式是否可启用，并确认账户国家、业务类别和 Stripe 账户状态都符合要求。客户位于某一国家，不代表商家的账户自动具备收款资格；反过来，商家在美国也要确认当前产品支持和账户限制。

## Checkout 中的客户流程

客户在 Checkout 选择加密支付后，Stripe 会把客户带到 crypto.stripe.com，连接钱包并选择代币和网络，再确认付款。客户完成后可返回商家网站。返回页面只是用户体验流程，不应成为履约的唯一凭据；订单状态仍需依据 Stripe 服务端对象和 webhook 处理。

建议订单系统区分“等待客户连接钱包”“等待链上付款确认”“付款成功”“支付失败或过期”等状态。客户可能在钱包授权过程中关闭浏览器，也可能因为网络拥堵或钱包拒绝而未完成交易。应用应提供重新查询订单状态的入口，避免用户重复付款或商家提前交付。

使用动态支付方式的 Checkout 或 Elements 集成，可以在 Dashboard 中启用稳定币付款并让 Stripe 按上下文显示。若手动配置付款方式，需根据当前 API 和产品文档确认支持方式，不能用银行卡支付方式的代码直接替代。

## 交易限额和捕获限制

Stripe 文档当前列出客户单笔交易上限为 10,000 USD。金额验证应在服务端完成，结合商品小计、税费、折扣和其他费用检查最终总额。若交易超过限额，商家可以提供其他合规付款方式，不应通过拆分订单来规避平台限制。

稳定币付款不支持手动捕获。需要先授权、后确认最终金额或多次部分捕获的业务，应在集成前评估不支持手动 capture 的影响。若库存或订单金额可能在支付后变化，需要在创建 Checkout Session 时就确定客户应支付的金额和商品内容，而不是期待后续调整授权金额。

Stripe 当前列出稳定币付款支持 recurring payments，也支持 Connect 和 Billing；但具体订阅、发票和账户功能需按 Stripe 当前集成说明验证。自动续费不意味着每次付款都保证成功，商家仍需处理发票、订阅和付款状态。

## 退款必须回到客户原钱包

Stripe 文档说明，稳定币付款支持全额和部分退款，但退款始终以稳定币形式返回客户原始钱包。商家不能把退款改成银行转账、另一个钱包或其他代币网络，除非采用 Stripe 之外的独立退款流程并遵循自己的政策。退款金额和到账资产应以 Stripe 对象和支付方式规则为准。

退款请求提交后，应追踪 Refund 状态并等待最终结果。客服应说明退款会退回原钱包，而不是承诺退回本地货币账户。若客户原钱包无法访问或希望换一个钱包，需按照 Stripe 当前流程和商家政策处理，不要在 Checkout 页承诺任意地址退款。

对账时记录原始 Stripe 付款对象、代币和网络信息、当地货币结算金额、退款对象及最终退款状态。客户支付代币价值与商家当地货币结算金额可能因交易时点和转换机制而不同，因此财务系统要以 Stripe 交易和余额流水为准。

## 争议与消费者支持

Stripe 文档列出稳定币支付不支持传统争议或信用卡拒付流程。客户完成钱包认证后，不会以常见银行卡争议方式从 Stripe 余额扣回款项。不过，商家仍需保留订单和履约记录、响应客服请求并遵守适用的消费者权益和退款规定。没有卡片拒付机制不代表商家可以忽略争议、合规或客户支持。

客服应能查到 Stripe PaymentIntent、Checkout Session 和订单状态，处理客户误付、付款重复、商品未交付或钱包连接问题。若商家主动决定退款，按 Stripe 支持的稳定币退款流程处理。

## 安全与运营建议

- 只使用 Stripe 提供的支付流程，不要求客户把稳定币转入商家手动提供的地址；
- 不在日志、客服工单或公开页面保存钱包敏感凭据；
- 服务端验证客户订单、金额、币种和支付状态；
- webhook 验证签名并实现幂等，避免重复履约；
- 监控不同网络的付款成功率、确认时间和退款状态；
- 财务对账使用 Stripe 余额与交易对象，而非手工计算代币汇率；
- 明确网站上的退款、交付和客服政策；
- 对 private preview 能力设置独立的上线检查和访问范围。

## 上线检查清单

- 商家账户国家符合当前稳定币支付资格；
- private preview 账户已获 Stripe 开放；
- 目标客户所在地区不属于受限制范围；
- 当前商品和结账流程以受支持的 USD 展示币种为准；
- 接受的代币和区块链网络在 Dashboard 中实际可用；
- 单笔金额不超过 10,000 USD；
- 订单不依赖手动捕获或部分捕获；
- 测试钱包连接、客户取消、付款确认和页面未返回；
- webhook 验签及幂等处理正常；
- 退款流程明确返回客户原始钱包；
- 财务系统按 Stripe 当地货币余额和流水核对；
- 客服能处理链上、钱包和订单状态问题。

## 总结

Stripe 稳定币支付支持客户通过钱包使用指定代币和网络付款，商家结算收到 Stripe 账户本地货币。当前支持的代币、网络、商家国家和 private preview 资格各不相同，且客户单笔金额有 10,000 USD 上限。稳定币付款不支持手动捕获，退款会以稳定币返回原始钱包，也没有传统卡片拒付争议流程。

上线前应确认商家资格、具体代币网络、结算和退款体验，并测试 Checkout、Webhook 和钱包异常路径。客户支付状态以 Stripe 服务端记录为准，财务对账使用 Stripe 余额和交易流水。规则和 preview 状态可能变化，以 Dashboard 和 Stripe 官方文档为准。
