# Stripe Klarna 争议处理：21 天询问期、证据提交和退款边界

Klarna 争议的处理方式与银行卡拒付不完全相同。多数 Klarna 争议会先以 inquiry（询问或查询）形式出现，留给商户一段时间直接联系客户、解释订单或处理退货。若问题在规定期间内未解决，才会升级为 chargeback（拒付争议），届时资金可能被暂扣，商户也需要提交证据。最容易造成损失的错误，是把 inquiry 当成已经可以提交证据的拒付，或忽略它直到升级后才开始联系客户。

本文说明 Klarna 争议的阶段、时限、退款边界和证据准备方式，并给出将 Webhook 接入客服工单的做法。不同原因码和例外情况可能有不同流程，处理每个案件时要查看 Stripe Dashboard 中的当前状态、截止日期和争议详情。

## 先区分 inquiry 和 chargeback

客户可以在 Klarna 应用中针对具体订单提交投诉或退货请求。Stripe 文档指出，客户通常可在付款 capture 后最多 180 个日历日提出争议。大部分争议先进入 inquiry 阶段，典型处理窗口为 21 个日历日。欺诈等某些情况可能直接升级，不能假设每个案件都会经过完整询问期。

两个阶段的主要差异如下：

| 项目 | Inquiry 询问阶段 | Chargeback 拒付阶段 |
| --- | --- | --- |
| 目的 | 让商户知道客户遇到问题，尽量直接解决 | 争议正式进入拒付裁决流程 |
| 商户首要动作 | 联系客户、核对订单、处理符合条件的退款或退货 | 根据原因整理并提交证据 |
| 是否可提交证据 | Klarna 不接受 inquiry 阶段的证据 | 可以提交证据，但要在截止时间前一次性准备完整 |
| 资金处理 | 客户尚未完成的分期还款可能暂停 | Stripe 会暂扣争议金额和相关争议费用 |
| 退款 | 在 inquiry 阶段可通过全额退款处理；部分争议要核对金额 | 已升级的争议不能再按普通流程发起该笔付款退款 |
| 时间限制 | 多数案件 21 天后会自动升级 | 从升级时起通常有 12 天提交证据；欺诈案件为 5 天 |

Stripe 文档说明，Klarna 争议只收取一项与争议结果相关的费用：若商户最终赢得争议，Stripe 会释放暂扣资金及相关费用；若商户败诉，争议金额和费用会从余额扣除。具体费用以账户所在地区的 Stripe 定价页面为准。

## 在 inquiry 阶段优先解决客户问题

Stripe 一旦收到 Klarna inquiry，会通过 Dashboard、API 或事件通知商户。此时客户可能已暂停尚未到期的分期还款。Inquiry 的价值在于及时发现订单投诉，让商户有机会在争议升级前处理问题。此阶段不要急着上传材料，因为 Klarna 不接受 inquiry 阶段的证据。

商户可以采取以下操作：

1. **联系客户并确认诉求。** 通过可追踪的客服渠道确认是未收到商品、商品问题、重复付款还是退货请求。
2. **核对订单和履约。** 检查发货状态、物流轨迹、交付时间、商品清单和此前沟通。
3. **需要退款时及时处理。** 在 inquiry 阶段全额退款可以解决对应争议，避免继续升级。对于部分争议，应确认退款金额与客户退货金额一致。
4. **对退货请求查看客户提供的证明。** Stripe Dashboard 中的 Return inquiry 可能附有退货跟踪信息。确认退货在途或已送达后，按规则处理退款。
5. **记录沟通和决定。** 保存联系人、时间、处理方案和退款对象 ID，以便案件升级后继续追踪。

客户可以通过 Klarna 应用撤回 inquiry。如果商户与客户达成解决方案，要将沟通结果和退款状态保存在内部系统中，避免订单仍显示为待处理争议。

### 全额争议与部分退货不要混为一谈

若 Klarna 建立的是部分争议，商户可以提交与争议金额相等的部分退款来解决 inquiry。若客户只退回部分商品，但争议对象是整笔订单的全额金额，商户即使只退了部分款，也可能无法解决整个 inquiry；未解决案件仍可能在 21 天后升级。此时要记录客户实际退货的商品、剩余订单履约情况和部分退款凭证，以便升级后解释为何只应退还部分金额。

不要在不核对争议金额的情况下，对同一订单重复进行全额退款。客户投诉、Klarna inquiry 和商户 Refund 是不同对象，客服系统要明确它们之间的关联。

## 升级为 chargeback 后迅速提交完整证据

如果 inquiry 在 21 个日历日内未解决，案件通常会自动升级为 chargeback。此时 Stripe 会从余额中暂扣争议金额和相关费用。商户可以通过 Dashboard 或 Disputes API 提交证据，截止日期会显示在 Dashboard，也可以从 Dispute 对象的 evidence_details.due_by 字段读取。

Klarna 拒付阶段有两个重要限制：

- 普通 chargeback 通常只有 12 个日历日提交证据；欺诈争议的提交窗口为 5 天。
- 每个 Klarna 争议只能提交一轮证据。材料不足或原因填写不准确，后续补充机会可能受限。

因此，系统收到升级事件后应立即通知所有需要提供材料的团队，不要将内部截止时间设在官方截止日当天。至少预留审核时间，检查日期、金额、客户标识和附件是否对应同一订单。

按原因准备材料：

| 争议原因 | 常见材料方向 |
| --- | --- |
| 未收到商品 | 承运商、追踪号、发货日期、签收信息、客户沟通 |
| 客户已退货或退款未处理 | 退货跟踪、退款请求和处理结果、退款政策说明 |
| 重复付款 | 原始订单、付款记录、与客户的解释沟通 |
| 未授权购买 | 订单及客户沟通、发货地址和交付凭证 |
| 商品有问题 | 商品描述、售后沟通、退换货方案和客户确认 |
| 订单信息不正确 | 订单明细、购物车项目、价格及交付信息 |

材料要围绕争议原因展开，避免提交互相矛盾的物流和退款日期。Stripe 文档建议按 Dashboard 争议详情中的推荐证据类型准备材料。API 上传证据时，相关文件需要通过 Stripe Files API 上传，再把文件 ID 关联到 Dispute。官方文档还指出，上传的证据文件应仅用于单个争议；不同案件不要复用同一个上传文件 ID。

## 退款与争议升级之间的边界

Stripe 文档说明，Klarna 付款最多可在付款完成后的 180 天内提交全额或部分退款。Klarna 会取消这笔订单剩余的分期付款，并把客户已经支付的金额返还给客户；退款通常需要 5 到 7 个工作日，也可能因金融机构或购买类型而更久。

对于部分退款，Klarna 会调整订单总额。如果退款金额超过订单剩余未付金额，Klarna 会先扣减未付余额，再将差额返还客户；退款低于剩余余额时，退款金额会抵扣未付余额并分摊至剩余分期。多个部分退款加总不能超过原交易金额。

但是，Klarna 文档指出，付款进入争议后不支持再提交普通退款。因此，在 inquiry 阶段应尽快判断是否应退款；一旦升级为 chargeback，应按争议流程提交证据或接受争议，不要重复创建退款造成状态和账务不一致。退款和拒付争议是不同路径，系统需要在状态机中明确互斥和转换条件。

## 用 Webhook 自动创建争议任务

Stripe 会为争议生命周期发送事件。接收端应先验证 Webhook 签名，再保存事件 ID 和 Dispute ID，并进行幂等处理。事件可能重复投递，工单系统不能因此创建多条完全相同的争议任务。

至少可跟踪以下信息：

- Dispute ID、PaymentIntent ID、Charge ID 和内部订单号；
- Stripe 争议原因、Klarna 原因和当前阶段；
- inquiry 创建时间、预期升级时间；
- 证据截止日期 evidence_details.due_by；
- 退款对象及金额；
- 客户联系记录、物流或服务交付材料；
- 证据负责人、复核人、提交时间及最终结果。

Stripe 文档指出，charge.dispute.funds_withdrawn 可以用于跟踪争议升级至 chargeback 的资金扣留阶段。应用还应根据争议对象的更新状态判断是否已经升级，不能仅按固定时间推算。若事件处理失败，应从持久化记录重试，并以对象当前状态为准。

建议把争议队列分成两个工作视图：“需要客户沟通的 inquiry”和“需要证据提交的 chargeback”。inquiry 阶段自动提醒客服联系客户；升级后立即转交争议负责人并生成 12 天或 5 天的证据时间表。

## 测试和团队操作检查清单

Stripe 提供 Klarna Sandbox 争议测试数据，可用于模拟部分争议对象和验证证据提交流程；Sandbox 不能模拟最终裁决结果。测试重点应放在内部流程是否能收到通知、创建去重任务、关联订单、设置截止日期和保存材料，而不是依赖测试环境推断实际胜诉率。

上线或更新客服流程前确认：

- [ ] 团队理解 inquiry 和 chargeback 是不同阶段。
- [ ] inquiry 阶段不会误上传证据，因为 Klarna 不接受此阶段的证据。
- [ ] 有人负责在 21 天窗口内联系客户并判断退款或退货。
- [ ] 部分争议退款金额与实际退货金额一致。
- [ ] Chargeback 阶段能读取 Dashboard 截止时间或 evidence_details.due_by。
- [ ] 12 天期限和欺诈案件 5 天期限有负责人及内部提前提醒。
- [ ] 证据一次性准备完整，附件和订单确实对应。
- [ ] 争议升级后，普通退款操作会被拦截或要求人工复核。
- [ ] Webhook 验签、去重、重试和工单状态转换已经测试。

## 总结

Klarna 争议的关键是尽早处理 inquiry。多数投诉先提供约 21 天窗口，商户应联系客户、核对退货或退款并争取在升级前解决。升级为 chargeback 后，处理重心转为准备一次性证据提交，并按通常 12 天、欺诈 5 天的期限行动。

退款在争议升级前后有明确边界，证据提交也不能套用银行卡流程。建议在系统中把 inquiry 和 chargeback 分开建队列，使用 Webhook 记录阶段变化和截止日期，并保留退款、订单履约和客户沟通的完整关联。
