# Stripe Climate 使用指南：Commitments 与 Orders 如何选择和管理碳移除

Stripe Climate 为企业参与碳移除提供了两条不同的路径：Climate Commitments 按收入的一定比例投入，帮助早期碳移除技术发展；Climate Orders 则允许企业购买特定数量的碳移除量，适合需要明确采购数量或希望将碳移除产品提供给客户的业务。两者都围绕碳移除，但用途、财务规划和对外表达方式并不相同。

企业在启动前应先回答一个问题：目标是长期支持碳移除行业，还是需要购买可计量的特定吨数？前一种通常更适合按收入比例作出 Commitment；后一种则应评估 Orders 的库存、供应方、交付和记录。即使使用 Stripe 的产品，也不能因此自动宣称产品已实现碳中和，或把碳移除抵消与自身减排混为一谈。

## 一、先区分两种产品目标

Climate Commitments 适合希望持续支持碳移除领域、但不需要购买固定吨数以满足某个目标的企业。企业可以设置将收入的一定比例用于 Climate 的承诺，让金额随着业务收入变化。这种模式容易与商业增长衔接，能在公司规模扩大时同步增加支持额度。企业仍需把承诺比例、核算口径和内部批准流程说清楚，避免员工或客户误以为每笔销售都已购买一份等量碳移除。

Climate Orders 适合需要采购特定数量碳移除量的企业，也可以用于想把碳移除选项提供给自身客户的场景。企业可通过 Stripe Dashboard 或 Climate API 进行购买；Stripe 文档说明库存可能用于即时或未来交付，企业可以购买组合产品，也可以选择单个供应商。因为购买的是基于项目和交付安排的产品，采购前要检查可用库存、供应方信息、交付时间和相关披露，而不是只将吨数记入宣传材料。

简单判断：若企业目标是为行业早期发展提供持续资金，先评估 Commitments；若企业必须获取某一数量并需要跟踪交付安排，重点评估 Orders。两种路径都应与公司的气候目标、财务授权、会计政策和对外声明审核流程配套。

## 二、确认地区与 Dashboard 可用性

Stripe Climate Orders 官方页面列出的可用地区包括美国、欧盟、加拿大、英国、日本、列支敦士登和挪威。账户资格、购买币种、产品供应和 API 能力可能随 Stripe 产品更新而调整，因此企业应登录自己的 Dashboard 检查实际可用选项，并在计划面向多个法人实体或多地运营时逐一确认账户范围。不能仅凭网站访客所在国家推定该企业账户已经具备 Climate Orders 购买资格。

不写代码也可以通过 Dashboard 下单；需要将碳移除采购整合进内部产品、采购和数据流程时，可进一步评估 Climate API。Dashboard 适合先由财务或可持续发展负责人理解产品、测试审批流和观察可用库存。API 更适合重复性采购、自动同步采购记录或将产品嵌入客户体验，但需要额外建设调用权限、异常处理和审计日志。

建议先在内部制定采购职责：谁可以发起、谁批准金额、谁复核供应方及数量、谁负责接收交付材料、谁负责在财务系统中记账。若组织采用多 Stripe 账户，应明确采用哪个账户进行采购，避免同一业务在不同法人或平台账户下重复计算。

## 三、Climate Commitments 的规划和数据口径

按收入比例投入时，企业要定义“收入”具体指什么：是 Stripe 处理的总金额、扣除退款后的净销售额，还是会计系统确认的收入？Stripe 产品中的实际计算方式和 Dashboard 配置应以账户页面与官方文档为准。企业内部财务指标不一定与支付处理额一致，因此应把营销展示口径与账务核算口径分开，确保财务团队能按同一规则复核。

承诺比例设置过高可能给现金流和毛利带来压力；设置很低却在宣传中使用夸张表达，则会损害客户信任。可以先按照历史交易额、退款比例、季节波动和毛利率模拟年度投入，再由财务和管理层批准比例。订阅型业务应考虑续费和退款周期，促销活动也可能令短期交易额大幅波动，不能简单使用某一个高峰月份推演全年预算。

内部记录建议包含产品路径、承诺比例、启用日期、业务收入口径、累计金额、退款调整、对账周期、批准人和披露版本。若公司在某个时点修改承诺比例，应保留前后配置和生效日期，不能用当前比例回算整个历史年度。

## 四、Climate Orders 的采购与交付管理

通过 Orders 采购时，先明确要购买的是多少吨、用于什么业务目标、预计何时交付，以及是否希望选择特定项目或采用组合产品。Stripe Climate 与 Frontier 的产品安排涉及供应方和长期采购关系；官方资料说明碳移除会由 Frontier 和独立第三方进行验证后交付。企业应阅读当前库存页和披露，了解具体供应方、移除路径、交付约定和限制。

采购记录不应只保存订单金额。至少应保存 Stripe Climate 订单标识、采购时间、数量、币种和金额、产品或供应方信息、预计交付时间、实际交付文件以及内部批准记录。若采购由 API 发起，调用方需要记录请求与响应标识，确保在超时重试后不会产生重复下单；对无法确认是否已创建订单的情况，应先查询状态，再决定是否发起新请求。

如果企业把碳移除加入客户购买流程，应明确客户购买的是何种产品或支持选项、客户付费金额是否独立展示、相关款项如何核算、订单失败或退款时如何处置。客户可能理解为自己购买了一定数量的碳移除，而企业实际只是代表客户进行采购或将收入的一部分用于支持。页面文案和条款应准确说明资金流、数量计算方式、交付凭证和可能的时间差。

## 五、API 集成和内部控制

API 集成前，先阅读当前 Climate API 文档，确认可用操作、请求字段、身份验证方式、地区资格和速率限制。Stripe API 密钥应只保存在服务器环境变量或受控密钥管理系统中，绝不能暴露在前端脚本、公开代码仓库或客户浏览器。为生产和测试环境分别使用对应凭据，部署权限也应只授予实际需要发起或查看采购的服务。

涉及下单的接口应设计幂等保护和状态核对。服务器发生超时，不代表请求一定没有成功；重试前需遵循 API 的幂等机制，并将请求 ID 和内部采购编号持久化。对于创建成功但业务数据库写入失败的情况，应安排对账任务补齐记录，而不是直接再次购买。给财务团队的采购列表应能通过内部采购编号追踪 Stripe 订单和后续交付信息。

权限策略方面，可让普通运营人员查看采购进度，而金额审批、配置承诺比例和正式下单权限由少量授权用户掌握。定期检查 API 密钥使用人、Dashboard 角色、离职人员权限和生产日志。日志中避免记录密钥、敏感客户数据以及不必要的完整请求内容。

## 六、会计、退款和客户披露

碳移除采购的会计分类取决于企业适用准则、具体合同和交易实质，Stripe Climate 产品本身不会替公司决定应如何记账。财务团队应与会计师讨论支出确认时点、承诺与实际采购的区别、未来交付的处理、税务和发票要求。客户退款、订单取消或支付争议也可能影响与订单相关的碳移除预算，需预先定义是撤销、保留还是单独承担采购金额。

宣传内容应区分企业运营减排、碳抵消、碳移除采购和支持行业发展。若企业只是将一定比例收入投入 Climate Commitments，通常不应把每一笔商品销售描述成购买了固定吨数的碳移除。若通过 Orders 购买了特定数量，也应以实际采购与交付材料为依据，明确项目和时间范围，并避免作出超出证据的“零碳”“碳中和”结论。

Stripe 的 Climate 页面强调其资金用于碳移除项目并指出可能存在第三方收费；某些贡献可能不是可抵税的慈善捐赠。企业不要把 Stripe Climate 误称为公益捐款或慈善机构，也不要承诺客户可以取得捐赠抵税资格。应依据具体产品条款和本地税务建议撰写客户说明。

## 七、常见问题排查

**Dashboard 找不到 Climate。** 确认登录的是正确的 Stripe 账户，并核对业务国家和产品可用性。不同产品路径的地区范围不一定完全相同；若账户资格不清楚，应联系 Stripe 支持，不要用其他账户代下单后再假设可以转移记录。

**API 调用超时，不确定是否下单成功。** 先根据请求标识和幂等机制查询或重试，检查 Dashboard 与内部采购记录，不要立即重复创建。超时重试策略应在集成开发时设计，而不是等财务发现重复订单再手动修正。

**已下单但看不到交付凭证。** 检查该产品的预计交付安排和订单状态，确认下单的供应组合与交付时间。记录与客户披露要区分“已采购”“等待交付”和“已完成验证交付”等阶段。

**市场文案把收入比例写成吨数。** 立即核对 Climate Commitment 的配置和实际采购记录。收入承诺金额不能直接换算为固定吨数，除非存在经核实的计量和采购依据。

## 八、企业上线检查清单

1. 明确目标是持续支持碳移除领域，还是购买特定数量。
2. 核实 Stripe 账户地区、Climate 产品资格和当前库存。
3. 对收入百分比定义统一的内部计算口径，并由财务批准。
4. 为 Orders 明确吨数、项目组合、预计交付和采购审批人。
5. 对 API 密钥、幂等请求、超时重试与采购状态核对进行设计。
6. 保存订单标识、数量、金额、币种、供应方、交付时间及凭证。
7. 对客户承担的金额、退款和碳移除采购之间关系作出说明。
8. 让会计和法务审阅记账、税务、客户条款及气候声明。
9. 不将收入承诺表述为固定吨数或慈善捐赠。
10. 定期核对 Dashboard 配置、支付数据、财务台账与交付材料。

## 总结

Stripe Climate 的 Commitments 与 Orders 服务于不同决策。Commitments 适合按收入比例持续支持碳移除行业；Orders 面向需要采购特定数量并跟踪供应与交付的企业。前者需要定义收入计算和预算口径，后者需要管理采购审批、数量、供应方和交付记录。

上线前应检查账户资格和当前产品信息，并让财务、可持续发展、工程与法务共同确认流程。对外表达应严格依据实际承诺、采购和交付情况，不把支持行业发展说成固定吨数，也不把碳移除采购误作慈善捐款或未经核实的碳中和结论。
