优惠活动常用于首单折扣、订阅试用转付费、限时促销或指定客户补偿。Stripe Billing 中，Coupon 描述折扣规则，Promotion Code 则是客户在结账时输入或使用的兑换码。二者有关联，但不是同一个对象。把折扣期限、兑换限制、适用产品和续费行为设计清楚，才能避免客户看到的金额与商家账单预期不同。

优惠券配置会影响 Checkout、订阅、发票和收入报表。一次性折扣、持续若干周期的折扣和永久折扣对客户账单有不同影响；优惠结束后，续费价格也可能变化。本文介绍对象关系、业务规则、结账和订阅测试以及常见配置问题。字段和产品行为以 Stripe 当前文档与账户配置为准。

## 一、Coupon 和 Promotion Code 的区别

Coupon 描述折扣本身，例如固定金额折扣、百分比折扣或适用期限。Promotion Code 是客户可能使用的代码，并可指向一个 Coupon，同时附带客户、有效期或兑换次数等限制。一个折扣规则可以设计成特定促销码供客户输入，也可由业务在创建支付或订阅时按规则应用。

产品团队应先明确折扣策略，再配置 Stripe 对象。需要回答：折扣是首期还是多期？适用于一次性付款还是订阅？能否与其他折扣叠加？哪些产品可用？一个客户能兑换几次？活动何时开始、何时结束？如果只创建一个 Coupon，却没有限制 Promotion Code，客户可能重复兑换或把码传播到不符合条件的人群。

优惠名称和内部记录也要清楚。保存 Coupon ID、Promotion Code ID、活动名称、批准人、适用产品和结束日期。客户界面展示优惠码时，明确显示优惠金额和有效期，避免只写“优惠已应用”却不说明下一期将恢复原价。

## 二、设计折扣金额与期限

创建促销前，确认采用固定金额还是百分比折扣，是否有最大优惠金额，折扣适用于哪些行项目，以及税费如何计算。不同产品价格和币种可能导致固定金额优惠效果不同。若活动面向多个国家或币种，逐项确认适用规则，不要假设一张优惠券在所有币种都产生相同经济效果。

订阅折扣要明确持续周期。例如仅首张发票优惠、前几期优惠或永久折扣。客户可能在优惠期内升级、降级、取消后重新订阅，业务要定义折扣是否保留。Stripe 对具体期限和订阅变更的处理应在测试环境验证，并用发票预览核对金额。

折扣结束后，客户账单可能恢复到标准价格。产品应在价格页、结账页或邮件中解释未来续费金额和时间。若价格随活动期间变化，保存活动规则版本，避免客服无法回答“为什么本期比上期贵”。不要把“首期折扣”宣传成整个订阅周期都是同一价格。

## 三、Promotion Code 的限制

Promotion Code 可根据业务设置客户限制、可兑换次数或失效时间等条件。对公开活动，可以设置总兑换上限和结束时间；对客户补偿，可以限制特定 Customer。若公开页面展示优惠码，客户可能转发给其他人，因此应使用适合的限制方式，并监控兑换情况。

代码需具备清晰规则，避免难以辨认的字符、大小写混淆或过期后仍长期展示。虽然 Stripe 对活动代码的唯一性和字段有具体要求，但平台仍需要定义自己的优惠活动命名和审计规范。停用某个 Promotion Code 与删除已经应用到订阅上的折扣不是相同操作，要分别确认。

如果允许客户自行输入代码，前端需要显示无效、过期、不适用或已达到上限等状态，并避免暴露内部错误。服务端也要校验兑换结果与用户、产品、金额和活动条件，不能完全依赖浏览器提交的信息。对于已登录客户绑定的优惠码，要从服务器确认 Customer 身份。

## 四、在 Checkout 和 Payment Links 中使用

使用 Checkout 时，可以按 API 配置允许客户输入 Promotion Code，或由服务器根据活动规则应用优惠。公开输入框适合广泛活动；自动应用优惠适合已验证资格的客户。两种方式都要核对最终 Checkout Session 和 Invoice 金额，不要只看页面显示按钮。

Payment Links 的优惠配置应与产品 Price 和活动期限一致。发布前用测试客户实际打开链接，检查代码能否兑换、商品是否适用、税费与折扣如何展示，以及支付成功后订单保存了哪些对象。链接可能被公开转发，内部优惠或客户专属价格不要放在没有保护的公共页面。

对于一次性付款，确认优惠是否只作用于指定商品或数量；购物车多商品时，要测试优惠如何分配到行项目。若客户输入多个代码，页面应清晰展示是否允许叠加。折扣变化应反映到订单记录，后续退款要参考实际成交金额和原发票明细。

## 五、订阅折扣和续费处理

将 Coupon 用于订阅时，折扣可能影响当前发票和之后多个周期。系统要监听订阅与发票 Webhook，保存实际应用的折扣、优惠期限和每期应付金额。不要仅在本地保存“用户用了优惠”，却无法确认 Stripe 是否将折扣应用成功。

订阅中途升级、降级或取消时，折扣如何处理要预先明确。按比例计费、优惠期内切换 Price 和客户取消后重新订阅，可能产生与简单首期优惠不同的账单。测试新订阅、续费、升级、降级、付款失败、取消和重新开通情形，逐张对比 Stripe Invoice 和内部预期金额。

退款或贷项调整时，确认原发票实际扣款和优惠分配。不能按照优惠前的标价退款，也不能把折扣金额错误算成平台应退现金。财务账本应保存原始 Price、Coupon、Promotion Code、最终行项目金额、税额和 Refund 关联。

## 六、数据分析和防止促销滥用

活动期间监控代码兑换数、转化率、客单价、退款、续费和活动后留存。兑换量突然增加可能说明促销被公开传播，也可能是营销渠道效果好；结合客户和订单数据判断，不要只凭代码使用次数做结论。限制规则和监控要兼顾用户体验，避免误伤合法活动受众。

平台可设置每个客户的兑换政策和活动总量预算。对高价值商品或订阅，服务端验证用户是否满足活动资格。不要在公开客户端埋入私有 Coupon ID 后假设没人能发现；可通过后端逻辑控制可用优惠，并记录触发来源。若发现异常兑换，停用相应 Promotion Code，并核对已创建的 Checkout Session 或订阅。

## 七、测试、客服与常见错误

测试有效代码、过期、超限、不适用产品、客户限制、折扣期限结束、订阅续费、套餐变更、退款和重复提交。验证测试与生产 Coupon 分离，营销页面与 Stripe Dashboard 中的设置一致。客服工具应能查到客户是否兑换、优惠持续几期和下一次账单金额。

常见错误包括把 Coupon 当作客户输入代码、折扣期限设置错误、活动结束只删除营销横幅却忘了停用码、在多个 Price 上意外生效、误以为停用 Promotion Code 会撤销历史订阅折扣，以及不向客户说明折扣结束后的原价。排查时查看 Stripe 对象、发票行项目和活动配置，而不只依据客户截图。

## 八、SEO 与官方资料

介绍 Stripe 优惠功能的页面应说明 Coupon 与 Promotion Code 的概念差别、折扣期限、兑换限制和续费影响。标题聚焦具体任务，避免“永久免费折扣”等误导表达。促销活动页应写清价格、截止日期、适用条件和优惠后续费用，并及时更新过期内容。

## 总结

Stripe Coupon 定义折扣规则，Promotion Code 为客户提供可兑换的代码及限制。配置时明确折扣金额、适用产品、周期、客户资格、兑换上限和到期时间，并确认优惠结束后的续费价格。Checkout 和 Payment Links 要验证最终金额；订阅流程需通过 Webhook 和发票记录同步状态。

上线后分析优惠的兑换、退款和续费表现，发现异常时可停用代码并检查已有订阅。通过准确的营销说明、服务器端资格校验、幂等处理和财务对账，能减少优惠误用和账单争议。
