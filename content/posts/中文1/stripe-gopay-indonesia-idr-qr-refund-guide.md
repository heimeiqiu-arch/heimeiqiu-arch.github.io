GoPay 是在印度尼西亚使用的数字钱包支付方式。通过 Stripe 接入时，手机客户通常会跳转到 GoPay 或 Gojek 应用授权付款；桌面客户则可以用相应应用扫描二维码。对于想服务印尼消费者的跨境商家，这种应用跳转和二维码体验可能比单纯的国际银行卡表单更符合当地用户习惯。

GoPay 的使用范围和操作规则有几个容易忽略的特点：客户位于印度尼西亚，展示币种为 IDR；部分商家账户可以启用，但 Stripe Connect 平台或 Marketplace 不支持该方式；单次付款、保存支付方式后的重复付款及退款时限也不同。本文按照 Stripe 当前文档说明接入前的资格判断、IDR 金额校验、QR 流程、授权和退款对账。

## 先核对账户与客户范围

Stripe 当前 GoPay 文档列出的商家账户国家包括印度尼西亚、新加坡和美国，客户使用国家为印度尼西亚。可服务的商家国家和可使用钱包的客户国家不是同一张清单：比如企业账户位于新加坡，不代表新加坡客户可以使用 GoPay；目标客户应符合 Stripe 当前列出的 GoPay 使用地区。

文档列出 GoPay 可用于商户账户，业务模式可为 B2B 或 B2C，但不支持平台或 Marketplace 的 Connect 账户类型。因此，若商家通过 Connect 为多个卖家代收款，应先确认是否符合账户资格，不能把单商户集成代码直接用于平台账户。

Stripe 还提示，账户启用后可能会再审核 GoPay 资格。商家应提供符合 Stripe 账户激活要求的网站，并留意 Dashboard 中是否出现能力限制。业务类别也可能受到 Stripe 或 GoPay 的限制，正式上线前需要按自身 MCC 和账户情况核对。

## IDR 币种和金额规则

GoPay 面向位于印度尼西亚的客户，展示币种为 IDR。Stripe 文档列出的单笔最低金额为 0.50 美元或等值 IDR，最高金额为 20,000,000 IDR。客户 GoPay 账户的验证状态也会影响其单笔支付上限：未验证账户文档列出的上限较低，已验证账户则可达到该支付方式的最高金额。

IDR 是零小数币种，Stripe 文档说明所有价格末尾需要为 .00，不能将分数金额，例如 10,000.95 IDR，作为商品价格提交。金额校验应在服务端根据 Stripe 对 IDR 的货币规则处理，不要在前端把 IDR 当成两位小数货币并简单四舍五入。

价格、折扣、税额和运费都需要符合 IDR 及支付方式限制。创建 Checkout Session 前应验证所有 line item 使用正确币种，计算出最终金额并检查是否超过 GoPay 当前上限。若客户的订单金额超出单笔限制，可以按业务规则让客户使用其他支付方式，而不是拆单规避限制。

## 手机应用与桌面二维码流程

客户在手机上选择 GoPay 后，可能会被带到 GoPay 或 Gojek 应用进行授权；桌面端可以显示二维码供客户扫描。商家要确保结账页面解释“继续付款”后会发生的跳转，并提供返回订单页面的路径。二维码或应用跳转长时间未完成时，订单应保持待授权状态，而不是提前标记已付款。

用户可能在钱包授权后关闭商家页面，或者在应用和浏览器之间切换失败。服务端应通过 Stripe 的 PaymentIntent 或 Checkout Session 状态以及 webhook 确认结果。前端返回页面只负责刷新状态和显示结果，不应单独触发发货、发放权益或将订阅标记为已支付。

Stripe 文档将付款确认时机列为即时通知，结算时间则可能最长为 T+4 个工作日。商家在做财务报表时，应区分“客户已完成付款”和“资金已经按结算计划到达银行”这两个阶段。

## 重复付款授权和订阅

GoPay 支持重复付款。文档说明，客户可通过账户连接授权商家保存 GoPay 支付方式，并发起未来的 off-session 扣款。该多次使用授权允许可变金额的后续扣款，直到商家解绑保存的 PaymentMethod，或客户在 GoPay/Gojek 应用中取消与商家的连接。

订阅页面应清楚显示金额或计价方式、收费周期、何时开始扣款、如何取消。保存支付方式与未来扣款授权应按当前 Stripe 集成和适用规则处理，不要把一次钱包授权解释成无限制扣款许可。Webhook 应用于同步订阅、发票和支付状态，客户取消关联后还需要更新商家侧订阅流程。

上线前要测试首笔授权、保存方式、后续续费、客户在钱包应用中解除关联、商家主动解绑和付款失败。应用不能只依赖初次 PaymentIntent 的成功状态推断未来续费一定会成功。

## GoPay 退款时限要按交易类型区分

Stripe 文档对退款期限作了区分：

- 一次性 GoPay 付款通常需要在原付款后 45 天内提交退款；
- 保存 GoPay 后产生的初始付款和之后通过该保存方式进行的付款，文档列出的退款窗口为 180 天；
- 若客户使用非 Gojek 应用扫描二维码付款，超过原始付款 7 天后提交退款可能失败；
- GoPay 支持全额退款、部分退款和多次部分退款，但累计退款不能超过原始付款金额。

这些时限和二维码应用条件都应以 Stripe 当前文档为准，客服不要使用一个统一退款 SLA 覆盖所有 GoPay 订单。退款提交后通常几分钟可完成，但在一些情况下可能最长需要 20 天；提交后不能取消退款。

退款对象保持 pending 时，商家应向客户说明退款仍在处理中，不要提前承诺款项已退回钱包。监听 refund.updated 和 refund.failed webhook，成功时更新订单退款状态；失败时金额会返回 Stripe 余额，商家需要使用其他方式把款项退给客户。客服后台应记录客户使用的支付应用或交易上下文，方便判断适用的退款期限。

## 争议与客服处理

Stripe 文档指出，GoPay 不支持标准的卡组织争议或拒付流程，客户若对付款有疑问，需要联系商家。客户服务团队应提供清晰的订单号、付款时间、商品和退款政策查询路径，并建立从客户投诉到人工调查或退款的流程。

不支持标准 chargeback 并不代表商家不需要保留订单和履约记录。客服仍应能够核验付款是否成功、商品是否交付、客户是否联系过商家以及是否已经退款。若决定退款，仍须遵守 GoPay 的退款能力和时间限制。

## 上线测试清单

- Dashboard 显示 GoPay 可用，商家账户通过资格审核；
- 商家账户属于支持国家，目标客户位于印度尼西亚；
- Connect 平台或 Marketplace 不误用该方式；
- 商品、折扣和运费金额采用 IDR 且无小数金额；
- 金额符合最低和最高限额；
- 手机应用跳转和桌面二维码都完成测试；
- 支付成功、失败、取消和未返回页面都正确处理；
- PaymentIntent 状态和 webhook 驱动订单履约；
- 保存支付方式和订阅的未来扣款授权已单独验证；
- 45 天、180 天和二维码 7 天规则已写入客服系统；
- 退款 pending、成功和失败都能正确更新；
- 财务区分付款确认和 T+4 结算。

## 总结

Stripe GoPay 可以让印度尼西亚客户通过 GoPay 或 Gojek 应用授权，或在桌面端扫描二维码完成付款。接入时要确认商家账户资格、印尼客户范围、IDR 零小数格式和金额限制；该方式不支持 Stripe Connect 平台或 Marketplace 账户。

GoPay 支持重复付款和订阅授权，但客户或商家可以解除授权。一次性付款、保存方式后的扣款和二维码退款有不同退款期限，退款又是异步且提交后不能取消。把这些规则纳入服务端状态、订单对账和客服流程后，再开放给目标客户。
