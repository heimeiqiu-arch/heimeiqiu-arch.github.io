在 Stripe 中设置商品价格时，团队不仅要确认价格数字，还要决定这个价格是已经包含税款，还是税款会在结账时另外加到价格上。这个选择通常由 tax_behavior（税行为）表达：inclusive 表示价格包含税，exclusive 表示税款在商品价格之外计算。它会影响客户看到的总价、发票行项目、退款对账和不同市场之间的价格展示。

如果商家把含税价误设为未税价，客户可能在结账时看到比广告标价更高的总额；反过来，把未税价误当含税价，也可能让商家承担原本应单独收取的税款。本文介绍两种行为的差别、默认值、商品和运费的处理方法，以及如何在上线前验证最终金额。涉及税务义务和地区政策时，应让专业税务顾问结合实际业务确认，Stripe 的技术配置本身不替代税务判断。

## Inclusive 与 Exclusive 的区别

使用 exclusive 时，税款是在商品基础价格之上计算。假设商品未税价格为 100，适用税率为 10%，结账总额在其他费用之前会包含 100 的商品金额和 10 的税款。客户看到的价格通常会随着适用税率和地址改变。

使用 inclusive 时，商品展示价格已经包含税款。以同样的 100 总价为例，系统会将该价格拆分为商品净额和其中包含的税额；具体拆分依赖适用税率和税务规则。此时价格对客户而言更像含税标价，但商家最终可确认的商品净收入会低于标价中的总额，因为一部分金额对应税款。

含税与未税的差异不等同于“是否启用 Stripe Tax”。税行为决定如何解释价格金额；税务计算功能负责根据订单、客户地点、商品税码和商家注册情况等计算适用税额。商家需要把两个配置一起考虑。

## 商品价格与账户默认值

Stripe Price 可以在商品价格层面指定税行为。Stripe Tax 设置也可以定义默认税行为，用于价格未显式指定 tax_behavior 的情况。官方 API 文档中列出 exclusive、inclusive 和 inferred_by_currency 等默认选项；哪些选项适用于当前账户及产品，应以 Dashboard 和正在使用的 API 版本为准。

如果 Price 已经明确设置为 inclusive 或 exclusive，账户默认值就不是该价格的实际解释依据。团队应清点现有 Price，确认税行为是否明确、是否存在历史价格，以及 Payment Links、Checkout Sessions、Subscriptions 和 Invoices 是否引用了预期的价格对象。不要只查看 Dashboard 中某一个默认开关，就假设所有历史价格都会被改写。

上线前可以采用“旧价格盘点 + 新价格创建验证”的方式：

1. 导出正在销售的 Price ID、币种、金额、产品、周期和 tax_behavior。
2. 确认每个市场的标价承诺是含税还是未税。
3. 对 tax_behavior 未指定的价格，检查 Stripe Tax 当前默认设置。
4. 在测试环境创建新订单并查看商品行、税额和总额。
5. 分别检查订阅首期、续费、发票和退款的结果。
6. 保存价格与税务配置的变更审批记录。

根据 Stripe API 说明，一旦将价格税行为明确设为 inclusive 或 exclusive，不能像普通描述字段那样随意切换。需要更换定价模式时，应先查当前对象是否允许更新；通常要考虑创建新的 Price、调整产品引用或配置 Stripe Tax 默认值，而不是直接假定旧 Price 可以原地修改。

## 如何选择适合的标价方式

面向消费者直接展示固定总价的业务，可能希望标价保持稳定且包含税款；面向企业客户、报价和发票场景，业务也可能采用未税价格，并在发票中单独列税。不同国家或地区的法律和商业习惯并不完全相同，不能仅凭行业惯例决定某个市场应该采用哪一种。

商家可以把以下问题交给产品、财务和税务负责人一起确认：

- 网站上的价格文案是否明确写出含税或未税；
- 不同客户地址是否会影响税额；
- 商品和服务是否适用不同税务分类；
- 客户在 Checkout 中看到的总额是否与广告和报价承诺一致；
- 发票是否需要分开展示净额、税额和含税总额；
- 多币种价格是否每种币种都采用相同的税务展示逻辑；
- 促销折扣、运费和订阅续费是否按预期计税。

切换价格模式之前，先明确“客户看到的价格”和“会计系统记录的价格”分别代表什么。若销售团队、网站、发票和财务对账对同一价格的理解不同，即便 Stripe 正确计算，商家仍可能面临报价争议。

## 结账总额与税额拆分

Stripe Tax 会根据可用的交易信息计算税额。客户地址或配送地址、商品税码、价格税行为、商家税务注册地和订单日期等条件可能影响计算结果。商家要检查 Checkout、Payment Links 和订阅账单上的金额展示是否与业务承诺一致。

对于 exclusive 价格，页面应让客户理解税款可能额外加入总价；对于 inclusive 价格，则应检查税额是否以适当方式在收据或发票中显示。不同平台页面的金额格式可能略有差异，但订单的商品金额、税、运费、折扣和最终总额应能够对账。

运费也需要单独关注。如果运费需要纳税，其 tax_behavior 和税码可能与商品行不同。Stripe Tax 交易对象可以分别记录 line item 和 shipping cost 的税务金额与行为。不要只验证商品的含税设置而漏掉运费，否则客户会在结账最后一步看到意外金额变化。

## 订阅与价格切换

订阅价格会影响首次账单和之后每期续费。若为既有订阅替换 Price，或从月付切换为年付，税行为和价格金额需要一起核对。客户从含税价格切换到未税价格时，最终付款金额可能变化，即使新的基础金额看起来相同。变更日期、按比例费用、折扣和税额也可能共同作用。

建议对以下订阅情形单独测试：

- 新建订阅的首张发票；
- 试用期结束后的第一笔付款；
- 自动续费发票；
- 升级、降级或更换价格；
- 部分退款和全额退款；
- 客户地址变更后适用税额的变化。

不要仅根据 Price 对象上的 unit_amount 推断客户最终支付金额。发票和 Checkout Session 中还可能包含税、折扣、运费、余额调整和其他项目。后端应从 Stripe 生成的最终对象读取金额，再关联内部订单做财务对账。

## 常见配置错误

**标价写含税，Price 却按未税解释。** 结账页会在基础金额上另加税，最终总额高于营销页面。检查商品 Price 的税行为和页面文案。

**以为 Stripe Tax 自动决定所有商品价格的含税方式。** Stripe Tax 可提供计算和默认设置，但价格对象可能有自己的明确税行为。逐项核对 Price。

**只检查商品，遗漏运费。** Shipping cost 有独立金额和税务字段，需要确认是否应税以及如何展示。

**默认值更改后以为旧价格都更新。** 已明确设置税行为的 Price 不一定受账户默认值影响；历史订阅也要单独核实。

**只验证 Checkout，不验证发票和退款。** 订阅续费、税额拆分和退款会进入不同的 Stripe 对象和财务流程，必须做完整测试。

**把技术设置当成税务结论。** Stripe 配置不会替代商家对注册义务、销售地点和商品类别的判断。

## 上线检查清单

- 每个在售 Price 都有明确的含税/未税决策；
- 核对 Stripe Tax 默认 tax_behavior 与 Price 上显式值；
- 商品税码与业务内容匹配；
- 运费的金额、税码和 tax_behavior 单独确认；
- Checkout 页面展示价格与营销页描述一致；
- 测试不同客户地址和币种的税额差异；
- 验证订阅初次付款、续费、套餐切换和退款；
- 订单后台能对账商品金额、折扣、运费、税额和总额；
- 更新价格时评估现有订阅和旧 Price 的影响；
- 由财税负责人确认目标市场的实际税务处理。

## 总结

Stripe 的 inclusive 表示价格已包含税款，exclusive 表示税款在基础价格之外计算。Price 上明确设置的税行为、Stripe Tax 默认值、商品税码、客户地点、运费和订阅周期共同决定客户最终看到的账单。错误理解含税与未税，容易造成价格承诺不一致和财务对账偏差。

上线前逐个核对 Price 与默认设置，使用真实测试订单检查 Checkout、发票和退款金额。对于税务义务和市场规则，由专业税务人员确认后再落实到 Stripe 配置；技术字段只负责执行规则，不负责替商家判断规则。
