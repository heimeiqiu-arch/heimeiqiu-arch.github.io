# Stripe Terminal 读卡器软件更新：升级前检查、连接失败与门店运维

Stripe Terminal 读卡器既有设备软件，也需要与 POS 应用中的 Terminal SDK 配合工作。门店遇到连接不上读卡器、地区要求版本不符合、或者 SDK 提示必须安装更新时，容易把这些都当作“网络问题”。实际上，读卡器型号、地区、软件版本、SDK 版本和更新流程之间存在依赖关系；如果只在收银高峰期临时重启设备，可能延长停机时间，甚至影响当天营业。

本文介绍如何区分读卡器更新和应用 SDK 更新，怎样为多门店制定升级流程，以及连接或升级失败时该收集哪些信息。Stripe 会按支持范围更新设备和 SDK 要求，型号的生命周期也会变化。请以 Dashboard、当前 Terminal 文档和设备实际提示为准，不要将其他地区或其他型号的版本号直接套用。

## 先区分三种版本

排查前先确认团队讨论的是哪种软件版本：

| 层次 | 运行位置 | 主要影响 | 常见检查入口 |
| --- | --- | --- | --- |
| POS 应用版本 | 商户的手机、平板或收银设备 | UI、订单逻辑、调用 SDK 的方式 | 企业应用发布系统 |
| Terminal SDK 版本 | POS 应用依赖库 | 读卡器连接、收集和确认支付、更新回调 | 项目依赖文件和发行说明 |
| 读卡器软件版本 | 智能读卡器或移动读卡器 | 设备运行、地区功能和支付兼容 | Dashboard 或读卡器设置页面 |

三者升级节奏不同。应用团队可以发布新版本而不更换读卡器软件；SDK 更新也不一定意味着读卡器固件已更新。某些地区或设备型号可能要求达到指定读卡器版本后才能处理支付，另一些设备会在特定连接流程中检测更新。记录版本时写明型号、序列号、门店、SDK 版本和读卡器显示的软件版本，避免只记录“最新版”。

## 为什么要安排更新计划

读卡器软件可能包含地区认证要求、兼容性改进和安全维护。Stripe 的 Terminal 文档会针对不同型号和地区列出具体的软件要求；这些信息不能一概而论。若商户使用的读卡器长期未连接、门店网络限制设备下载，或设备在首次部署时没有完成初始配置，版本可能落后于当前要求。

更新过程也会占用门店时间。设备可能需要保持供电和网络连接，更新期间不能用于收款；部分移动读卡器的更新还可能要求一定电量。因而门店应在开店前、闭店后或低峰期处理更新，并预留备用设备或其他受支持的收款方案。不要等到顾客排队时才第一次让设备检查软件。

多地点运营可维护一个设备台账，包含门店名称、设备型号、序列号、设备状态、软件版本、最后在线时间、所在国家、绑定 Location 和更新负责人。每次采购、换机、维修、退役后都更新台账。这样看到某门店使用地区不匹配的读卡器时，能快速核对，而不是依靠店员口头描述。

## 升级前的准备工作

先在 Dashboard 或 Stripe 管理界面确认读卡器的登记状态、所属 Location、最近在线时间和设备型号。再核对当前 SDK 是否满足项目要求、设备固件是否有待处理更新，以及 Stripe 是否公布了该型号的终止支持或生命周期安排。对 Connect 平台运营者，还要明确哪些操作由平台、商户或场地管理员负责，确保门店知道更新通知和截止时间。

安排升级窗口时，建议准备：
- 一台测试设备或非高峰期的试点门店。
- 当前 POS 应用和 SDK 的发布版本，以及对应回滚或降级计划。
- 门店网络可访问所需服务的确认，及可联系的网络管理员。
- 读卡器供电、充电线和备用设备。
- 更新前后的版本记录和验证人员。
- 更新期间使用的人工收款或暂停销售流程。

更新之前不要进行未验证的批量操作。先选一台设备走完流程，确认重新连接、测试付款、退款或其他关键交易动作均正常，再逐个门店扩展。若 SDK 版本同时升级，先阅读 SDK changelog 和迁移要求，并在测试环境验证应用逻辑，避免把设备故障和代码变更混为一个问题。

## 更新时常见的阻塞原因

读卡器无法更新时，按“设备条件—网络—应用流程—版本支持”逐层排查。

**供电或电量不足：**确认电源线、充电状态和设备电池。某些移动读卡器在需要安装更新时要求至少达到最低电量，具体阈值以 Stripe 支持文档为准。避免连续强制重启导致更新中断；先记录屏幕上的提示和状态，再按对应型号步骤操作。

**网络不稳定或被防火墙拦截：**设备可能已连接 Wi-Fi，但无法访问更新服务或 Stripe 端点。检查 DNS、代理、防火墙和访客网络隔离，确认设备与 POS 应用在连接方式要求的网络环境中。不要仅以手机能正常浏览网页证明读卡器网络可用；读卡器的出站规则和本地发现方式可能不同。

**Location 或地区配置不匹配：**Terminal Location 的地址、账户国家和读卡器所在国家可能影响支付可用性。确认设备绑定的是正确地点，尤其是移动设备曾跨门店调拨或由其他账户登记的情况。不要临时更改 Location 地址来绕过产品限制；先确认实际业务地点和账户配置。

**应用和 SDK 调用不匹配：**某些设备类型通过 SDK 工作，更新检测和安装需要集成回调配合；不适用于该读卡器类型的操作可能返回功能不可用错误。确认所用 SDK 文档中对读卡器型号的说明，检查更新回调是否接入，避免对智能读卡器套用移动蓝牙读卡器的更新代码。

**设备状态或支持周期问题：**设备如果长期未上线、被替换或已接近生命周期终点，可能需要专门排查。查看 Stripe 对应设备的生命周期页面，确认是否仍有完整的软件更新和技术支持。对于已过支持范围的型号，应规划换机，而不是无限尝试安装新的固件。

每次排查只改变一个条件并记录结果。例如先确认供电，再确认网络，再重新尝试连接；避免同时更改路由器、防火墙和应用版本，否则成功或失败原因都难以定位。

## 更新后的验证和审计

更新完成后，不要只看读卡器屏幕回到首页。POS 应用应重新发现或连接设备，并执行受支持的测试流程，确认读卡器能够显示金额、等待客户操作、返回交易结果并与订单正确关联。测试模式和正式模式要区分清楚，避免用真实扣款测试而没有退款计划。

建议更新记录至少包含：更新前后版本、开始和完成时间、读卡器型号及序列号、门店 Location、操作员、应用与 SDK 版本、更新结果、异常日志摘要和验证付款结果。若支持中心要求提供诊断材料，就能直接提供可复现的信息。日志中不要记录 API 密钥、完整卡数据或客户不必要的个人信息。

大规模升级后监控门店级的连接失败、更新失败和付款失败趋势。如果仅某一型号或某个地区异常，及时暂停后续批次并收集具体设备信息；如果某个应用版本升级后多个门店同时失败，应考虑回退应用或 SDK，而不是要求每个店员重复重置设备。

## 门店维护清单

1. 每月核对读卡器型号、门店 Location 和软件版本。
2. 关注 Stripe 对设备更新、地区要求和生命周期的通知。
3. 在低峰时段为更新留出时间，准备备用设备或临时收款方案。
4. 先在试点设备上更新，再按门店小批次推广。
5. 更新后核实 SDK 连接、读卡器显示、测试交易和订单同步。
6. 记录失败设备和环境，不对同一问题反复执行无记录的重启。
7. 设备维修、跨店调拨、换机和退役时同步更新资产台账。

## 总结

Stripe Terminal 维护需要同时管理 POS 应用、Terminal SDK 和读卡器软件。先核对设备型号、所在地、Location 和当前版本，再安排供电和网络条件，分批升级并在每批后验证真实业务链路。遇到失败时记录设备与 SDK 版本、网络环境、提示内容和时间，按官方型号文档排查；对停止支持或地区不适用的设备，应计划替换，而不是依赖临时重启。
