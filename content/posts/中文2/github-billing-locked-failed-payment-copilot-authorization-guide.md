GitHub 账户出现计费锁定时，可能看到付费功能不可用、GitHub Actions 或某些免费层功能受影响，或者尝试订阅 Copilot 后账户仍提示付款问题。GitHub 官方文档特别说明：Copilot 注册或提高预算时的授权保留失败，也可能锁定个人账户的账单状态，即使用户打算继续使用 GitHub Free、已经删除付款方式，或账单页面看不到有效 Copilot 计划和余额。

这和普通的“银行卡被拒后换卡”不完全相同。先进入账户或组织对应的 Billing & Licensing 页面，检查是未付款账单、被拒交易还是失败授权保留，再按官方说明更新付款资料或提交支持请求。不要反复新增 Copilot 订阅，也不要假设移除卡片就能立即解除已有账单锁定。

本文聚焦 GitHub 个人账户、Copilot 订阅以及 Actions 等功能因账单授权问题受到影响的情况。组织账户、企业账户和个人账户的设置入口不同，处理前确认问题属于哪一个账户。

## 一、区分账单欠费和授权保留失败

登录 GitHub 后打开个人设置的 Billing & Licensing，查看账单状态、当前计划、付款方式和待解决问题。组织管理员应切换到对应组织设置中的 Billing & Licensing；企业账户则在企业管理区域查看。不要只查看个人账号，如果 Copilot 席位由组织分配或 Actions 由组织预算管理，个人账单页可能没有对应信息。

GitHub 官方列出两类常见情况：付款被拒后付费功能可能被锁；Copilot 注册或增加预算时的失败授权保留也可能导致个人账单锁定，并影响 GitHub Actions 或其他免费层访问。页面没有活动订阅，不一定表示没有需要处理的账单限制。

检查账单页面显示的具体提示和付款历史，记下日期、金额、账户类型、订阅名称和错误代码。不要仅凭银行 App 中一条 Pending 交易判断 GitHub 已完成扣款；需要同时对照 GitHub 的交易记录和银行状态。

## 二、检查付款方式并更新资料

在 Billing & Licensing 中打开 Payment information，核对保存的银行卡或 PayPal 资料。检查卡片是否过期、账单地址是否准确、账户余额或可用额度是否充足，以及发卡行是否允许线上或跨境交易。更换或补发卡片后，GitHub 账户可能仍保存旧资料。

GitHub 官方针对被拒付款建议更新账单资料，重新授权付款；付款方式可以编辑或移除。更新前先看是否有活动订阅、未结账单或组织共享支付设置，避免误删其他服务使用的付款方式。提交新的付款资料后，重新查看页面确认状态变化，而不是连续操作多次。

如果使用 PayPal，检查 PayPal 账户是否正常、关联银行卡或余额是否可用，以及是否有待处理授权。银行拒付时联系发卡行，询问是否因线上、安全验证、境外交易或账户限制造成。GitHub 页面如果明确显示授权问题，应按其官方账户恢复说明处理。

## 三、处理 Copilot 订阅与授权失败

如果锁定发生在订阅 Copilot Pro、Pro+ 或其他计划时，确认购买是否真正完成，查看 Billing & Licensing 中的计划状态和付款历史。GitHub 官方说明，注册 Copilot 或增加预算时发生的失败授权保留，可能影响个人账户计费，即使没有显示有效 Copilot 订阅。

不要在状态不明时再次点击升级或购买。先确认银行交易是失败、Pending 还是已正式入账，再检查 GitHub 账户有没有待处理的问题。若银行显示正式扣款而 GitHub 仍没有订阅或继续锁定，记录交易参考编号并通过 GitHub Support 请求核对。

如果你只是想使用 GitHub Free，应先查看账单锁定页面的解决办法。GitHub 文档提到，账户或组织可降级为 GitHub Free，以继续使用公开仓库中的相应高级功能；但授权保留导致的计费锁定可能仍需按照支持流程处理，不能只通过取消订阅或删除卡片来解决。

## 四、检查 Actions 和免费功能的影响范围

账单问题可能影响账户的付费功能；在特定授权失败情形下，GitHub 官方也指出 Actions 或其他免费层访问可能受到阻止。若 Actions workflow 失败，先确认失败发生在账单限制还是代码构建本身。查看 Actions 页面错误信息以及账户 Billing & Licensing 状态，不要把每个 CI 失败都归因于付款。

如果个人账户和组织均有账单设置，确认仓库属于哪个所有者，以及 Actions 计费预算由哪个账户控制。组织仓库的管理员可能需要处理组织账单，而个人用户无法修改组织付款资料。联系组织所有者或账单管理员时提供仓库名称、运行编号和相关账户提示，不要发送私人付款信息。

账单恢复后，再重新检查 Actions 使用、Copilot 计划和付费功能是否可用。某些功能状态可能需要刷新或重新登录，但如果 Billing 页面仍显示锁定，应先解决账单状态，而不是反复触发新 workflow。

## 五、识别 Pending 授权与银行正式扣款

银行卡出现授权保留或 Pending 时，资金可能暂时不可用，但这不一定是最终收费。GitHub 官方文档说明，付款方式更新后或计量服务使用增加时可能出现授权保留；GitHub 会立即发起释放，但银行或发卡机构可能需要几天才使资金重新可用。

因此，区分 GitHub 账单页面的应付余额与银行端临时授权。若 GitHub 显示付款失败而银行仅有 Pending，先确认授权状态，并等待银行处理，不要重复提交同一笔付款。若交易正式入账，但 GitHub 仍显示欠费或锁定，提供 GitHub 账户信息和银行参考编号请求官方核对。

如果银行明确拒绝授权，联系发卡行询问具体原因和可用解决方式。不要把完整卡号、安全码或验证码提交到 GitHub issue、公开仓库或支持评论中。账单问题应通过 GitHub 安全支持入口处理。

## 六、账户仍锁定时如何申请复核

如果 Billing & Licensing 页面没有活动计划、余额或待处理问题，但账户仍显示账单锁定，GitHub 官方文档建议通过 GitHub Support 请求复核。提交时说明锁定提示出现时间、账户是个人还是组织、是否尝试过 Copilot 或预算操作，以及 Billing 页面当前状态。

不要在工单里发送密码或一次性验证码。可提供必要的交易参考号、发票编号、账户用户名和错误截图，并遮盖卡号、账单地址等敏感内容。若发卡行确认存在拒付，也可附上银行提供的交易状态摘要。

如果锁定是因未结账单导致，GitHub 官方说明通过更新付款方式并恢复付费状态可解锁相关账户功能；文档也说明锁定期间经过的时间不会另行要求收费。具体应付金额、账户计划和组织权限以当前账单页面为准。

## 七、个人、组织与企业账户不要混淆

GitHub 的个人账户、组织和企业账户分别有账单页面和权限角色。个人用户可在个人 Settings 中找到 Billing & Licensing；组织账单通常需要组织所有者或具有相应权限的管理员；企业计费由企业管理人员处理。若你在个人页面看不到问题，确认是否应切换到账单实际所属的组织或企业。

Copilot 席位可能来自公司或开源项目的组织安排。个人账户收到的付款问题不一定能由组织管理员修复，反之组织账单锁也不一定能通过个人换卡解决。先确认 GitHub 提示关联的账户对象，再联系有权限的管理员或官方支持。

处理完后记录谁更新了付款方式、何时解除锁定以及哪些功能恢复。不要为排查问题而新建多个 GitHub 账号或在不同账号上重复订阅，这会增加账单归属和访问权限的混乱。

## 八、常见问题

**没有Copilot订阅，为什么GitHub账单仍被锁？** GitHub 官方说明，尝试注册 Copilot 或增加预算时失败的授权保留也可能锁定个人账户账单，即使页面没有活动计划或余额。

**删掉付款卡能自动解锁吗？** 不一定。检查 Billing & Licensing 的具体状态，并按官方说明更新账单资料或联系 GitHub Support 复核。

**GitHub Actions失败一定是付款问题吗？** 不是。检查 workflow 错误和账单页面；只有在账户授权或计费受限时，付款问题才是可能原因之一。

**银行有Pending记录代表GitHub已收费吗？** 不一定。授权保留与正式扣款不同，银行需要时间处理。对照 GitHub 付款历史与发卡行状态。

**组织仓库的计费锁应该找谁？** 先确认仓库所属账户和 Actions 预算由谁管理，再联系组织所有者或账单管理员处理。

## 总结

GitHub付款或授权失败造成账户锁定时，先在正确的个人、组织或企业账户中查看 Billing & Licensing。核对付款信息和交易状态，尤其注意 Copilot 注册或预算授权失败可能影响 Actions 与免费层访问。银行 Pending 不等于最终收费；更新资料后仍锁定或页面没有待处理事项时，通过 GitHub Support 请求复核。不要重复订阅或公开支付凭证。
