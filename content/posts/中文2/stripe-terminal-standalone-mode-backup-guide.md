Stripe Terminal 的智能读卡器通常由商家的 POS 系统发起交易、传入金额并接收支付结果。如果 POS 应用临时不可用，但读卡器本身仍能联网，门店可能希望直接在读卡器上继续收款。Stripe Terminal Standalone mode（独立模式）就是一种在支持的智能读卡器上不连接 POS 应用、直接由读卡器收款的备援方式。

独立模式不是所有 Terminal 读卡器都能使用，也不等于 Stripe 提供了一整套完整收银系统。根据 Stripe 当前支持资料，该模式处于 Public Preview，仅适用于指定读卡器，例如 Stripe Reader S700/S710 和 Verifone V660p。可用设备、预览资格和地区范围可能调整，部署前需在自己的 Dashboard 和官方文档里确认。独立模式还要求设备有互联网连接，不支持离线支付。POS 应用断开但读卡器仍联网，与读卡器本身断网，是两种不同故障。

## Standalone mode 适合什么场景

它主要适合简单、临时的备援收款：例如 POS 软件升级期间不能操作、店内网络服务正常但收银应用短时崩溃，或者门店需要在智能读卡器上直接输入一笔线下刷卡金额。员工可以在读卡器上发起支付，而不必等待 POS 应用恢复。

如果门店日常销售需要扫码商品、维护复杂商品目录、自动计算折扣和税费、管理库存、打印合规小票、同步客户会员或完成订单履约，仅有读卡器独立模式通常不足以取代 POS 系统。它处理的是收款这一环，不会自动补齐商品、库存、会计、税务和客户关系管理流程。

因此，在选择是否启用前，先写清备援场景：POS 软件坏了但互联网可用；POS 到读卡器连接出了问题；整个门店没有互联网；或只是收银员忘带 POS 终端。Standalone mode 适用于其中一部分场景，不能笼统理解为“读卡器任何情况下都能收款”。

## 与 Terminal 离线支付有什么区别

Standalone mode 要求读卡器可以连接互联网，交易由读卡器直接提交给 Stripe。离线支付则是在符合设备、SDK、配置和地区条件时，暂时把支付信息保存在读卡器或 POS 设备本地，待网络恢复后再转发。两者的触发条件、设备支持和交易状态都不同，不能把独立模式当作离线模式的开关。

| 情况 | Standalone mode | 离线支付 |
|---|---|---|
| POS 应用不可用，读卡器有互联网 | 可在受支持的读卡器上直接收款 | 视集成和配置而定 |
| 读卡器没有互联网 | 不支持 | 在支持的设备和场景下可能本地暂存 |
| 是否需要 POS 集成 | 不需要 POS 来驱动当前收款 | 仍取决于所用 Terminal 集成方式 |
| 交易何时送到 Stripe | 通过互联网直接处理 | 网络恢复后再转发并处理 |
| 主要限制 | 设备、预览资格和收银功能有限 | 需要额外风险控制，离线授权可能被拒 |

如果门店需要的是“没有互联网也能记录交易”，应阅读 Stripe Terminal 离线支付文档并对照自己的设备和 SDK；如果只是 POS 应用暂时不能使用但读卡器联网，才考虑独立模式。一定要用实际门店网络条件模拟测试，不要只靠功能名称判断。

## 创建 Location 并启用独立模式

Stripe Terminal Location 表示读卡器实际使用的门店或收款地点。启用独立模式前，先在 Stripe Dashboard 的 Terminal > Locations 中创建或选择正确的 Location。若是固定门店，应使用与该经营地点匹配的地址信息；若没有固定营业地点，按 Stripe 的 Location 配置指南选择合适的业务地址。

打开该 Location 的本地配置区域，进入 Standalone mode 标签并启用选项，保存更改。不同账户的 Dashboard 页面布局可能随版本更新，菜单名称略有变化时以当前 Stripe 界面和官方指南为准。不要只启用一个 Location，却把读卡器注册到另一个门店，否则设备行为和交易归属可能与预期不一致。

配置更新后，确认它已经应用到对应设备，再重新启动读卡器进入独立模式。若在设备上看不到独立收款入口，先检查账户是否获得预览资格、设备型号是否受支持、Location 是否正确、配置是否保存，以及读卡器是否完成重新启动。必要时在线重新连接并等待设备同步配置，不要反复切换多个 Location 进行试错。

## 注册读卡器并进入独立收款界面

购买或领用读卡器时，可以在 Dashboard 下单流程中选择已有 Location 预先注册设备；如果没有预先绑定，收到设备后也可以在读卡器设置中生成配对码，再通过 Dashboard 完成注册。注册完成后，确认设备显示的门店和 Location 与实际收银点一致。随后按照 Stripe 的设置说明重启设备。

启用 Standalone mode 后，读卡器的启动屏幕可进入独立收款流程。具体屏幕提示以实际硬件和当前固件为准。上线前由管理员和一线员工分别试操作一次，确认设备能正确显示金额、收款结果和收据选项。记录谁可以更改模式配置、谁可以发起退款，并把设备故障的升级联系人写入门店操作手册。

如果你想把 Standalone mode 当作临时备援，可以决定一直启用，或平时关闭、需要时再从 Dashboard 或自建 POS 配置流程启用。Stripe 支持资料还描述了使用专门 Location、配置和设备构成独立备援设备的做法。选择哪种方式取决于门店怎样管理设备、员工会不会误触模式，以及紧急时谁能修改配置。

## 读卡器上收款有哪些操作限制

Standalone mode 适合输入单笔金额并发起收款，但不提供常见 POS 商品目录或固定常用商品价格。每次支付尝试都要在设备上输入金额；如果需要合计多项金额，可按设备提供的计算方式处理。订单行项目、商品 SKU、库存扣减和优惠券等业务信息仍需在商家自己的系统中记录。

这意味着独立模式下读卡器成功处理支付后，商家仍要把该交易和真实订单对应起来。Stripe 官方资料说明可为独立模式支付添加内部备注，备注写入 PaymentIntent 的 `x_terminal_standalone_note`，可从 Dashboard 或 API 查看，并非顾客可见内容。门店可为收据或订单保留唯一编号，方便日后匹配，但不要在备注里写完整卡号、登录密码或其他敏感资料。

顾客收据方面，读卡器可在成功付款或退款后提供输入电子邮件的选项；失败交易不能通过该流程发送电子邮件收据。若商家本身必须提供纸质小票、订单明细或税务凭证，需要确认这些需求由哪套 POS 或财务系统完成。仅有银行卡扣款凭证并不自动等于商品销售明细或满足当地所有收据要求。

## 退款、权限与设备安全

Stripe 支持资料说明，独立模式下可从读卡器、Dashboard 或 Refunds API 发起退款。门店需要先制定统一的退款流程：以哪一个支付对象作为原交易依据，如何按权限批准退款，如何关联退货订单，谁负责在 POS 或财务系统登记退款结果。若员工既能从读卡器退款又能从 Dashboard 操作，应通过退款编号和原订单编号做同步，避免两边重复发起。

设备可以设置退款 PIN，以要求退款操作时进行设备侧验证。门店应限制设备管理员与退款权限，妥善保管 PIN，并在员工离职、设备丢失或权限调整时及时更新管理措施。读卡器不能脱离安全管理独立放置在顾客可自由操作的位置，也不应将管理员凭证交给无授权人员。

退款和收款都会形成 Stripe 支付对象或退款对象。POS 或订单系统应保存可核对的业务编号、金额、币种、操作人和时间；Dashboard 的记录、读卡器收据及自有订单台账应保持对应。发生异常时，先核实 Stripe 对象状态，再决定是否重试或补录，不要因为屏幕短暂卡住就重复收费。

## POS 断开时怎样把独立模式作为备援

Stripe 支持资料提供几种备援安排。第一种是一直启用独立模式；此时读卡器启动屏幕可进入该模式，POS 应用连接后通常会恢复自己的优先控制。这样不必临时改账户配置，但员工可能误触独立模式。可通过设备设置调整启动屏幕行为或配置闲置计时器，降低误进入的机会。

第二种是平时关闭独立模式，POS 故障时再通过 Dashboard 修改配置；也可以由自有 POS 通过 API 调整相关模式。这样能降低日常误操作，但紧急时需要有管理员可登录 Dashboard 或已有经过测试的恢复流程。不要依赖某一位员工的个人手机或不在现场的管理员账号，否则 POS 出故障时可能无人能打开备用收款方式。

第三种方式是设立专门用于备援的读卡器、Location 和配置。日常销售和应急销售分开，可以让员工更容易辨认设备，也便于日终对账。但需要维护额外硬件、测试设备是否联网、更新固件、同步 Location 配置，并确保备援设备始终具备处理付款的资格。

最重要的是实际演练：拔掉 POS 应用的网络连接但保留读卡器互联网，观察员工是否能从 Splash screen 进入独立模式；再恢复 POS，验证它重新接管设备；最后核对两个阶段的支付是否都能在 Dashboard 中找到。演练要避免在真实客户交易中测试，可使用 Stripe 提供的测试环境和适当的模拟方式。

## 财税记录与合规边界

Stripe 明确提示 Standalone mode 是没有连接 POS 应用时收卡付款的辅助工具，例如主 POS 暂时不可用。它不能提供满足税务或监管要求的完整可审计交易记录，也不会替商家向税务机关提交销售数据。如果所在地区要求使用经过认证的收银机、税控设备或 POS 系统，独立模式不构成这些系统的替代品。

因此，应先确认门店订单、销售明细、税额、发票和会计记录会由哪套系统保留。如果 POS 暂停后所有销售都改在读卡器完成，可能需要之后手动或通过 API 补录到正式销售台账。财务团队应能将 PaymentIntent、金额、币种、Location、内部备注、日期和原始订单联系起来，以便日终复核。

本文不替代当地税务或监管判断。不同国家、行业和门店可能有额外收据、电子发票和交易记录要求。如不确定独立模式是否满足所在司法辖区要求，应向当地税务机关或合格的专业顾问确认，并继续使用规定的销售记录系统。

## 常见问题排查

**Dashboard 看不到 Standalone mode 标签**：确认使用的账户具有当前预览资格，Location 已创建，读卡器型号属于当前支持列表，并在对应 Location 的本地配置中查找。若预览资格或设备支持不明确，联系 Stripe 官方支持核实。

**读卡器重启后仍未进入独立模式**：核对设备是否注册到目标 Location、Standalone mode 是否保存启用、配置是否已经传播到设备，以及是否按要求重启。恢复网络后重新连接，让设备同步最新设置。

**POS 已断开，但读卡器也无法独立收款**：检查读卡器是否仍能访问互联网。Standalone mode 本身需要网络，不能解决读卡器断网。若需求是网络中断时继续收款，需要单独核查离线支付支持和风险条件。

**交易已从读卡器收取，但 POS 订单里找不到**：根据 Stripe Dashboard 或 API 中的 PaymentIntent，使用内部订单备注、金额、币种、时间和 Location 匹配自有销售记录。若门店此前没有统一订单编号，先将支付列为待核对记录，确认后再补账，避免误记或重复记账。

**有退款但 POS 未显示**：用原支付对象和 Stripe Refund ID 关联退款，检查是否由读卡器或 Dashboard 创建，再同步本地订单状态。建立退款的权限和审计流程，避免不同操作入口造成重复退款。

## 部署检查表

- 确认账户、地区和具体读卡器型号支持当前 Standalone mode 预览。
- 为正确门店创建 Location，并将设备注册到该地点。
- 在 Location 本地配置中启用该模式，按要求保存并重启设备。
- 明确读卡器必须联网，POS 无法用与读卡器断网要分别处理。
- 培训员工输入金额、核对付款和处理收据选项。
- 为独立模式交易准备内部备注或本地订单编号，方便日终匹配。
- 定义 Dashboard、读卡器和 API 多个入口的退款同步流程。
- 设置设备和退款权限，保管退款 PIN 和管理员凭证。
- 确认 POS 恢复后能重新接管设备，并演练误触恢复。
- 确认当地税务记录要求由正式 POS 或合规系统满足。

Stripe Terminal Standalone mode 可以在 POS 应用故障时提供有限的刷卡备援，但需要受支持的智能读卡器、正确 Location 配置和可用互联网。它不包含商品目录、完整订单管理或财税合规记录，也不能替代离线支付方案。把每笔独立收款映射回正式订单，并事前演练 POS 接管和退款同步，才能让这项备援功能可控、可审计。
