# Stripe 订阅扣款失败怎么办？先看交易是否可重试

Stripe Billing 的订阅续费付款失败后，商户需要区分可重试的发卡行拒绝、不可重试的 hard decline（硬拒绝）、没有保存付款方式，以及付款方式不支持自动重试等情形。打开 Stripe Dashboard 查看失败发票、PaymentIntent 和订阅状态，再判断是否开启重试或请求客户更新付款资料。不要对所有失败交易无限重复扣款。

Stripe 官方说明，Smart Retries 会根据付款行为和交易信号选择重试时机；新建的 Stripe 账户默认启用 Smart Retries。商户也可以设定自定义重试计划。具体失败处理会受账户设置、支付方式、拒绝原因、地区和付款网络限制影响。

## 一、先在 Dashboard 核对失败交易和订阅状态

进入 Stripe Dashboard 的 Billing，找到相关订阅和未支付发票，核对客户、账期、金额、付款方式及最后失败时间。查看交易返回的 decline code（拒绝代码）和 Stripe 提供的处理建议。不同拒绝原因对应的下一步不同：有些需要客户联系银行，有些需要修正卡片资料，还有些不应对同一交易继续重试。

同时查看订阅是否进入 past_due（逾期）状态，以及发票是否仍开放。付款失败、发票未结清和订阅被暂停或取消是不同状态，不能只根据客户邮件判断。若你的 Stripe 账户有自定义订阅生命周期设置，按当前配置处理，避免自动重试与人工补款同时发生。

## 二、确认 Smart Retries 或自定义重试计划

Stripe 官方文档说明，可在 Dashboard 的 Billing > Revenue recovery > Retries 查看订阅重试设置。Smart Retries 根据动态信号选择重试时机；如果商户需要特定节奏，也可配置自定义计划。不要假设 Smart Retries 使用固定日期或固定次数，登录自己的 Dashboard 查看实际规则。

重试前先判断拒绝代码是否允许再次尝试。Stripe 明确指出，卡组织可能限制单笔交易的重试次数；过多重试会被银行视为可疑行为，增加正常交易再次被拒的风险。参考 Stripe 返回的 advice code：若提示不要再尝试，应联系发卡行或让客户更新付款方式；若提示稍后再试，则按合理间隔重试；若卡片资料错误，则先修正资料。

## 三、哪些情况 Stripe 不会自动重试

Stripe 官方说明，以下情况不会自动重试订阅付款：没有可用付款方式；发卡机构返回硬拒绝代码；某些印度发行的银行卡；Stripe Connect 账户已断开；以及不支持自动重试的付款方式，例如 Cash App Pay 或 Amazon Pay。商户应按失败原因处理，而不是持续点击重试按钮。

如果没有保存卡片或客户需要完成额外验证，向客户发送安全的付款更新或认证流程。客户侧可以检查卡片有效期、账单地址、余额和银行安全验证，并联系发卡行确认是否允许线上或周期订阅扣款。商户不应通过邮件要求客户发送完整卡号、CVV、密码或短信验证码。

直接借记等支付方式需要使用相应的付款方式设置管理重试，而不能简单套用信用卡的重试配置。不同本地支付方式的失败处理能力也可能不同，应查看 Stripe 对该支付方式的当前支持说明。

## 四、更新付款方式时最容易忽略的优先级

Stripe 会按付款方式优先级选择重试对象。官方说明，系统会先看订阅默认付款方式，再看旧版订阅付款来源，然后看客户默认付款方式等。如果付款失败发生在订阅自己的 default payment method 上，商户只更新客户级的默认卡，Stripe 仍可能继续使用订阅上原先失败的那张卡。

因此更新方式时，先查看失败交易使用的付款方式挂在哪个对象上，再更新对应的订阅默认方式或客户默认方式。保存后重新打开订阅和发票，确认卡片显示在预期位置，并查看下一次重试计划。只在客户记录里增加一张卡，并不一定会改变已有订阅的优先付款卡。

## 五、客户认证和银行拒付的处理

发卡行拒绝交易时，Stripe 通常不会知道银行内部的完整原因。若 decline code 指向银行拒绝、账户限制或安全校验，客户需要通过银行卡背面电话或银行官方应用确认是否拦截了周期扣款、境外交易或网络支付，并完成所需验证。

若付款需要 3-D Secure 或客户主动确认，商户应使用 Stripe 提供的客户认证流程和发票支付页面。不要把验证步骤设计为客户向客服发送一次性密码。客户完成认证后，再核对 PaymentIntent 或发票状态是否变为已支付。

## 六、监控失败事件与客户通知

订阅运营团队可以监听 Stripe webhook 的 payment_intent.payment_failed 等事件，记录失败时间和返回原因，并触发客户通知或内部跟进。收到失败事件后，不要立即将账户永久关闭；根据订阅状态、发票状态、可重试原因和付款恢复配置决定是否暂时限制服务。

支付成功后再次核对 invoice 和 subscription 状态，再恢复客户权限。若 webhook 重复送达，应通过事件 ID 和交易对象去重，避免重复发送账单邮件或重复启动重试。客户通过银行转账或其他渠道补款时，也要把款项匹配到原发票，不要再向同一客户自动扣一次。

## 七、待处理授权、重复记录与对账

银行账单的 Pending（待处理）不一定代表 Stripe 已完成收款。对照 Stripe Dashboard 中 PaymentIntent、Charge 和 Invoice 的状态，确认是否已成功、失败或仍在认证。若银行已正式入账但 Stripe 发票仍显示未付，准备发票号、交易 ID、金额和银行参考信息，联系 Stripe 支持核实。

如果客户报告重复扣款，先查是否存在多笔真实成功付款，还是一笔成功交易加一笔待处理授权。保留每个交易编号和发票对应关系；确认实际重复入账后按退款流程处理。不要仅凭银行中相同金额的两条记录立即发起重复退款。

## 常见问题

### Smart Retries 会在固定日期重试吗？

Smart Retries 根据动态信号选择重试时间，不是对所有客户采用固定日期。商户可以在 Stripe Dashboard 查看当前重试设置，或按需要配置自定义计划。

### 更新了客户付款方式，为什么订阅还在尝试旧卡？

付款失败可能发生在订阅级默认付款方式。Stripe 官方说明重试有明确付款方式优先级；只改客户默认卡时，订阅仍可能使用自己的原付款方式。核对并更新发生失败的字段。

### 所有付款失败都可以自动重试吗？

不能。没有可用卡、硬拒绝代码、断开的 Connect 账户及部分支付方式都可能不支持自动重试。先看 Stripe 失败原因和 advice code。

### 订阅显示 past_due 就是取消了吗？

不一定。past_due 表示有未结付款，后续暂停或取消取决于 Stripe 订阅设置和恢复流程。查看 Dashboard 中订阅、发票和重试配置的实际状态。

## 商户排查清单

1. 打开失败发票，核对 PaymentIntent 状态和拒绝代码。
2. 判断交易是否可重试，避免对硬拒绝无限重试。
3. 检查 Smart Retries 或自定义重试设置。
4. 更新失败的订阅级或客户级默认付款方式。
5. 让客户通过银行和安全认证流程解决发卡行限制。
6. 监听失败和成功事件，对账后再调整服务权限。

如果你经营跨境 SaaS 或线上订阅产品，可以了解 CBPayments 的产品说明，核实覆盖地区、收款场景和合同条款后再评估。Stripe 的自动重试与付款方式兼容性取决于账户配置、地区和交易结果，第三方支付产品不能保证 Stripe 付款成功或订阅恢复。
